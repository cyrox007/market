# API Load Tests (k6)

Нагрузочные тесты генерируются из OpenAPI-спецификации и запускаются через [k6](https://grafana.com/docs/k6/latest/).

## Требования

- Node.js 20+
- [k6](https://grafana.com/docs/k6/latest/set-up/install-k6/) установлен в системе (например `brew install k6`)

## Команды (из корня репозитория)

```bash
# Сгенерировать скрипт из openapi.json
npm run api:perf:generate

# Запустить тест (предварительно запустите backend: php artisan serve или docker)
npm run api:perf:run

# Сгенерировать и сразу запустить
npm run api:perf
```

По умолчанию: 10 виртуальных пользователей, 30 секунд. Base URL по умолчанию `http://localhost:8000`; переопределение: `K6_BASE_URL=https://api.example.com npm run api:perf:run`. Если передать URL без схемы (`localhost:8000`), скрипт сам подставит `http://`.

## Отчёты

После `npm run api:perf:run`:

1. **В терминале** — в конце вывода k6 печатает сводку (итерации, запросы/сек, задержки, ошибки). Это и есть основной отчёт.
2. **В файле** — JSON-отчёт сохраняется в `tools/k6/reports/report.json`. Его можно открыть в редакторе или просмотреть в [Grafana](https://grafana.com/docs/k6/latest/analyze-results/). Каталог `tools/k6/reports/` в .gitignore.

Первый запуск создаст папку `tools/k6/reports/`, если её ещё нет.

## Почему часть запросов падает (401) и время большое

- **401 на logout и других защищённых маршрутах** — сгенерированный скрипт не передаёт cookies между запросами: после login ответ с Set-Cookie не сохраняется для следующих запросов, поэтому `/auth/logout`, `/auth/me` и т.п. идут без сессии и возвращают 401. Это ожидаемо для «сырого» сценария без cookie jar.
- **Большое время ответа** — для реалистичных цифр при нагрузочном тесте на backend рекомендуется:
  - **Redis** для кэша и сессий: в `.env` выставить `CACHE_STORE=redis`, `SESSION_DRIVER=redis`, убедиться, что Redis запущен (например, `docker compose up -d redis`). Без Redis сессии пишутся в БД/файлы, что под нагрузкой даёт высокую задержку и конкуренцию.
  - Первый прогон по каталогу прогревает кэш (мета фильтров, списки товаров); повторный запуск обычно даёт заметно меньшие задержки.
- **«No script iterations fully finished»** — сценарий делает много запросов подряд (регистрация, логин, каталог, корзина и т.д.). При 10 VU и 30–60 с ни одна итерация не успевает завершиться. Чтобы увидеть полные итерации, увеличьте длительность: `K6_DURATION=180 npm run api:perf:run` или уменьшите VU.
