# Прототип новой админ-панели

Отдельная React-админка проекта «Светофор Мебели».

Ветка всегда строится от актуального `develop`. Текущая база:
`41be4940614f77b4226eaca8c90ec9cbe3fc65fa`.

## Важно

Это больше не макет на демонстрационных данных.

Прототип подключён к локальному Laravel backend `svetofor.local`:

- товары — реальные;
- категории — реальные;
- комнаты — реальные;
- характеристики и их значения — реальные;
- заказы — реальные, пока только чтение;
- магазины — реальные;
- локации — реальные;
- склады — реальные.

Изменение основной карточки товара и настроек характеристики **сохраняется в реальную локальную БД**.

Перед проверкой рекомендуется иметь актуальную локальную копию базы или резервную копию.

## Что можно менять

### Товар

Через защищённый `/admin_sv/api/products/{id}` сохраняются:

- название;
- SKU;
- GTIN;
- описание;
- статус;
- приоритет;
- цена;
- цена до скидки.

Запись проходит через `ProductPolicy::update` и Laravel validation.

Характеристики, вариации и складские остатки товара уже читаются из реальной БД, но изменение этих связей пока не включено.

### Характеристика

Через защищённый `/admin_sv/api/attributes/{id}` сохраняются:

- название;
- slug;
- тип;
- участие в вариациях;
- использование в фильтрах;
- обязательность;
- множественность;
- разрешение ручного значения;
- порядок.

Запись проходит через `AttributePolicy::update`.

Значения характеристики пока читаются из реальной БД без изменения.

### Заказы

Заказы и состав читаются через административный endpoint с `OrderPolicy::viewAny`.

Изменяющие действия намеренно не подключены. По результатам аудита сначала необходимо исправить серверные риски вокруг возвратов, списания остатков, повторных действий и пересчёта итоговой суммы.

## Авторизация

Прототип использует ту же web-сессию, что Filament.

Vite проксирует `/admin_sv` на `http://svetofor.local`.

Если React показывает экран входа:

1. Откройте из прототипа `/admin_sv/login`.
2. Войдите обычным администратором.
3. Вернитесь на `http://localhost:5174`.

Права берутся из существующих Laravel Policy/Spatie Permission.

## Права на склады

Для склада добавлены отдельные:

- `viewAny warehouses`;
- `view warehouses`;
- `create warehouses`;
- `update warehouses`;
- `delete warehouses`.

Они создаются миграцией `2026_09_23_113000_add_warehouse_permissions.php`.

## Запуск

После переключения ветки:

```bash
cd services/backend
php artisan migrate
php artisan optimize:clear
```

Затем из корня репозитория:

```bash
npm install
npm run dev --workspace=svetofor-admin-prototype
```

Открыть:

```text
http://localhost:5174
```

По умолчанию Vite проксирует backend на:

```text
http://svetofor.local
```

Для другого адреса:

```bash
set ADMIN_BACKEND=http://localhost:8000
npm run dev --workspace=svetofor-admin-prototype
```

## UX-принципы

- минимум прокрутки всей страницы;
- отдельные рабочие области со своей прокруткой;
- крупные смысловые вкладки вместо длинной формы;
- обязательные поля видны сразу;
- ошибки backend показываются рядом с рабочей областью;
- права доступа влияют на доступность действий;
- редкие и опасные операции отделяются от обычного редактирования;
- React не дублирует бизнес-логику Laravel.

## Ограничения архитектуры по результатам аудита

Новая админка не должна переносить существующее поведение Filament один в один.

### Права доступа

- право «просматривать» не должно разрешать изменяющие или опасные операции;
- каждое изменение состояния должно проверяться backend;
- скрытие кнопки в интерфейсе не заменяет серверную проверку.

### Заказы, оплаты и возвраты

- создание заказа, изменение статусов, списание остатков, оплата и возврат должны быть целостными серверными сценариями;
- защита от повторного списания/возврата не должна зависеть от памяти PHP-процесса;
- изменение составляющих доставки должно сопровождаться серверным пересчётом итогов;
- UI не должен предлагать операцию, которую сервисный слой фактически не поддерживает.

### Импорт и 1С

- импорт из 1С должен быть отдельным рабочим процессом;
- импорт не должен самостоятельно сохранять сущность и затем повторно запускать сохранение формы;
- ошибки, конфликты и результат импорта должны быть явно видны оператору.

### Граница UI и бизнес-логики

- расчёты и правила предметной области остаются в Laravel;
- React обращается к явным административным командам/API;
- для опасных действий нужны серверная проверка, подтверждение и однозначный результат.
