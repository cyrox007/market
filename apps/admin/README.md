# Новая админ-панель

React-приложение новой административной панели проекта «Светофор Мебели».

## Структура

Вся клиентская часть админ-панели находится в:

```text
apps/admin
```

Включая:

- исходники React;
- Vite-конфигурацию;
- зависимости;
- статические ресурсы;
- собранный `dist`.

Laravel в `services/backend` содержит только административные API, политики доступа и бизнес-логику.

## Сборка

Рабочий сценарий под OpenServer:

```cmd
cd C:\OSPanel\home\svetofor.local\apps\admin
npm install
npm run build
```

Результат:

```text
apps/admin/dist
```

Сборка не копируется в `services/backend/public`.

Laravel отдаёт содержимое `apps/admin/dist` по адресу:

```text
http://svetofor.local/admin-ui/
```

Таким образом React и Laravel работают на одном origin `svetofor.local`, а существующая web-сессия Filament, cookies и CSRF используются без отдельного прокси-сервера.

## Подготовка после обновления ветки

```cmd
git fetch origin
git switch admin/react-prototype
git reset --hard origin/admin/react-prototype

cd C:\OSPanel\home\svetofor.local\services\backend
php artisan migrate
php artisan optimize:clear

cd C:\OSPanel\home\svetofor.local\apps\admin
npm install
npm run build
```

После этого открыть:

```text
http://svetofor.local/admin-ui/
```

Если административной сессии нет:

```text
http://svetofor.local/admin_sv/login
```

После входа вернуться в:

```text
http://svetofor.local/admin-ui/
```

## Товары: текущий UX

Экран каталога и форма товара разделены.

### Каталог

Экран `Товары и разделы` предназначен только для поиска и навигации:

- дерево категорий;
- дерево комнат;
- поиск по названию, SKU и GTIN;
- фильтр по статусу;
- сортировка по дате изменения, названию и цене;
- пагинация;
- список товаров с ценой, остатком, статусом и категориями.

Клик по товару открывает отдельный экран редактирования. При возврате сохраняются выбранный раздел, поиск и фильтры.

### Редактор товара

Редактор занимает отдельную рабочую область и содержит вкладки:

- Основное;
- Описание;
- Характеристики;
- Вариации;
- Остатки и доставка;
- Изображения;
- SEO / 1С;
- Связи.

Характеристики загружаются из двух источников:

- `product_product_attributes` — свойства самого товара;
- `product_variant_attributes` — свойства дочерних вариаций вариативного товара.

Значения вариативных характеристик агрегируются и показываются в карточке родительского товара.

## Реальные данные

Прототип работает с локальным Laravel backend и локальной БД:

- товары;
- категории;
- комнаты;
- характеристики и значения;
- заказы;
- магазины;
- локации;
- склады.

Изменение карточки товара, характеристик, вариаций, складских остатков, изображений и связей сохраняется в реальную локальную БД.

## Что уже сохраняется

### Товар

Через защищённые административные маршруты сохраняются:

- название, slug, SKU и GTIN;
- описание;
- статус и приоритет;
- цена и цена до скидки;
- категории и производитель;
- габариты, вес и предзаказ;
- налоговая и доставочная категории;
- обычные характеристики товара;
- набор параметров вариаций;
- торговые предложения и их характеристики;
- отдельные цены и остатки вариаций;
- складские остатки товара и вариаций;
- главное изображение и галерея;
- сопутствующие товары, комплекты и региональные правила.

Все изменяющие операции повторно проходят Laravel Policy и серверную валидацию.

### Характеристика

Через защищённый `/admin_sv/api/attributes/{id}`:

- название;
- slug;
- тип;
- участие в вариациях;
- использование в фильтрах;
- обязательность;
- множественность;
- разрешение ручного значения;
- порядок.

Запись проходит через `AttributePolicy`.

Из карточки товара можно без перехода в отдельный раздел:

- найти характеристику по названию или slug;
- создать новую характеристику;
- создать новое значение выбранной характеристики;
- сразу использовать созданную запись в товаре или вариации.

### Заказы

Заказы и их состав читаются через административный endpoint с `OrderPolicy::viewAny`.

Изменяющие операции пока не подключены. По результатам аудита сначала необходимо исправить серверную целостность возвратов, списания остатков, повторных действий и пересчёта итоговой суммы.

## Склады

Для складов добавлены отдельные разрешения:

- `viewAny warehouses`;
- `view warehouses`;
- `create warehouses`;
- `update warehouses`;
- `delete warehouses`.

Также используется отдельная `WarehousePolicy`.

Разрешения создаются миграцией:

```text
2026_09_23_113000_add_warehouse_permissions.php
```

## Архитектурные правила

- право просмотра не разрешает изменение;
- каждое изменение повторно проверяет Laravel;
- скрытие кнопки в React не заменяет Policy;
- денежные и необратимые операции не реализуются только в UI;
- расчёты и правила предметной области остаются в backend;
- изменение доставки должно приводить к серверному пересчёту итогов;
- защита от повторного списания или возврата не должна храниться только в памяти процесса;
- импорт из 1С должен быть отдельным рабочим процессом.

## Поведение на ноутбуках и узких экранах

Оболочка админки занимает ровно высоту viewport.

- внешний документ не имеет вертикальной прокрутки;
- отдельно прокручиваются дерево разделов, списки, таблицы и содержимое редакторов;
- верхняя панель и заголовки уменьшены, чтобы не съедать рабочую высоту;
- внутренние полосы прокрутки имеют единый компактный стиль;
- при ширине до 1100 px постоянный sidebar превращается в выезжающее меню;
- кнопка меню всегда остаётся в верхней панели;
- меню закрывается по крестику, клику вне панели, выбору раздела или клавише Esc.

## UX-принципы

- минимум прокрутки всей страницы;
- отдельные рабочие области со своей прокруткой;
- крупные смысловые блоки и вкладки;
- обязательные поля видны сразу;
- ошибки backend показываются рядом с рабочей областью;
- недоступные по правам действия не предлагаются оператору;
- редкие и опасные действия отделяются от ежедневного редактирования.


## Покрытие старой карточки товара

Функциональность старого редактора Filament разобрана по источникам и перенесена в отдельные рабочие вкладки.

### Основное

- название;
- slug;
- SKU;
- GTIN;
- статус;
- приоритет;
- цена;
- цена до скидки;
- категории;
- производитель.

### Описание

- HTML-описание товара.

### Характеристики

Обычные характеристики сохраняются через существующий `ProductAttributeSyncService`.

Поддерживаются:

- поиск характеристики по названию и slug;
- добавление и удаление характеристики;
- создание характеристики прямо из карточки товара;
- поиск значения;
- создание нового значения без ухода в справочник;
- множественные значения;
- ручное значение, если оно разрешено в справочнике;
- отдельная кнопка сохранения характеристик.

Характеристики вариаций не смешиваются с обычными свойствами родительского товара. Они отображаются отдельно и редактируются во вкладке вариаций.

### Вариации

Перед созданием торговых предложений оператор выбирает параметры, по которым они отличаются, например «Цвет» и «Размер». Недостающий параметр можно создать на месте.

Для каждой вариации поддерживаются:

- создание, изменение и удаление;
- собственные значения параметров;
- создание нового значения характеристики на месте;
- цена и старая цена;
- общий остаток либо отдельные остатки по складам;
- предзаказ;
- статус;
- внешний ID;
- главное изображение;
- отдельная галерея до 20 изображений.

### Остатки и доставка

Режим зависит от `ProductStockSettings::warehouse_accounting_enabled`.

Поддерживаются:

- общий остаток для простого товара;
- остатки по складам;
- предзаказ;
- системное количество продаж;
- длина;
- ширина;
- высота;
- вес;
- налоговая категория;
- категория доставки.

### Изображения

Используются реальные коллекции модели Product:

- `images` — главное изображение;
- `gallery` — галерея.

Для товара и каждой вариации:

- показываются реальные миниатюры;
- файлы можно выбрать через диалог или перетащить мышью;
- в галерею можно выбрать несколько файлов сразу;
- предел галереи — 20 изображений;
- файлы загружаются последовательно, чтобы сохранить исходный порядок;
- миниатюры можно перетаскивать для изменения порядка;
- новый порядок сразу сохраняется на сервере.

### SEO / 1С

- показывается динамический SEO-preview из текущей логики `MetaUniversalSEO`;
- показывается `external_id`;
- синхронизация из 1С вынесена в отдельную серверную команду;
- перед запуском явно предупреждается, что операция может изменить карточку, категории, производителя, характеристики, цены, остатки и вариации.

Ручные SEO-переопределения пакета `ralphjsmit/laravel-seo` пока не редактируются: в проекте нет собственного контракта для этой persisted-модели, поэтому поля не придумываются без проверки схемы пакета.

### Связи

- сопутствующие товары;
- комплекты/наборы;
- порядок элементов комплекта;
- региональные правила товара и вариаций.
