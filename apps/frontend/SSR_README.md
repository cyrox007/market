# SSR Руководство

## Обзор

Проект поддерживает Server-Side Rendering (SSR) с использованием Vite и Express. Все страницы рендерятся на сервере с полным HTML, что улучшает SEO и время первой загрузки.

## Архитектура

- **Express SSR Server** (`server/index.ts`) - обрабатывает все запросы и рендерит React на сервере
- **Entry Points**:
  - `src/entry-server.tsx` - серверный рендеринг
  - `src/entry-client.tsx` - клиентская гидратация
- **API для SSR** (`src/lib/api-ssr.ts`) - передает cookies из запроса в Laravel API

## Как проверить, что SSR работает

### 1. Проверка через View Source (Просмотр исходного кода)

1. Запустите SSR сервер:
   ```bash
   npm run dev:ssr
   ```

2. Откройте браузер и перейдите на любую страницу (например, `http://localhost:3000/product/divan-uglovoi-komfort-plius`)

3. Откройте исходный код страницы:
   - **Chrome/Edge**: Правый клик → "Просмотр кода страницы" или `Ctrl+U` (Windows) / `Cmd+Option+U` (Mac)
   - **Firefox**: Правый клик → "Просмотреть исходный код страницы" или `Ctrl+U` (Windows) / `Cmd+U` (Mac)

4. **Что искать:**
   - ✅ **SSR работает**: В исходном коде вы увидите полный HTML с содержимым страницы (заголовки, текст, изображения и т.д.)
   - ❌ **SSR не работает**: В исходном коде будет только `<div id="root"></div>` без содержимого

### 2. Проверка через DevTools Network

1. Откройте DevTools (F12)
2. Перейдите на вкладку **Network**
3. Обновите страницу
4. Найдите запрос к главной странице (обычно первый запрос)
5. Откройте вкладку **Response** или **Preview**
6. **Что искать:**
   - ✅ **SSR работает**: В ответе сервера будет полный HTML с содержимым
   - ❌ **SSR не работает**: В ответе будет только базовый HTML с пустым `<div id="root">`

### 3. Проверка через отключение JavaScript

1. В Chrome DevTools: `F12` → `Settings` (шестеренка) → `Debugger` → включите "Disable JavaScript"
2. Обновите страницу
3. **Что искать:**
   - ✅ **SSR работает**: Страница отображается полностью, видно содержимое
   - ❌ **SSR не работает**: Страница пустая или показывает только базовую разметку

### 4. Проверка через curl

```bash
# Запустите SSR сервер, затем выполните:
curl http://localhost:3000/product/divan-uglovoi-komfort-plius

# ✅ SSR работает: В выводе будет полный HTML с содержимым страницы
# ❌ SSR не работает: В выводе будет только базовый HTML с пустым <div id="root">
```

### 5. Проверка Initial State

1. Откройте исходный код страницы (View Source)
2. Найдите в `<head>` тег:
   ```html
   <script>window.__INITIAL_STATE__ = {...}</script>
   ```
3. **Что искать:**
   - ✅ **SSR работает**: Скрипт присутствует с данными пользователя и счетчиков (если пользователь авторизован)
   - ❌ **SSR не работает**: Скрипт отсутствует или пустой

### 6. Проверка в консоли сервера

При запуске `npm run dev:ssr` вы должны видеть:
```
SSR Server running at http://localhost:3000
```

При запросе к странице в консоли могут появляться логи загрузки данных (если включено логирование).

## Команды

### Разработка

```bash
# SSR режим разработки
npm run dev:ssr

# Обычный SPA режим (без SSR)
npm run dev
```

```bash

npm run build:ssr

# Запуск SSR сервера
```

## Особенности

1. **Cookie Forwarding**: Все cookies из браузерного запроса автоматически передаются в Laravel API
2. **Initial State**: Данные пользователя и счетчики загружаются на сервере и передаются в клиент через `window.__INITIAL_STATE__`
3. **Product Preloading**: Товары загружаются на сервере для страниц `/product/:slug`, что устраняет показ "Товар не найден" и ускоряет загрузку
4. **Region Detection**: Регион определяется на сервере и передается в клиент
5. **Error Handling**: При ошибке SSR приложение продолжает работать (fallback на SPA режим)
6. **SEO**: Все страницы рендерятся с полным HTML на сервере
7. **Hydration**: После загрузки HTML происходит гидратация React приложения на клиенте

## Переменные окружения

- `NODE_ENV` - режим работы (development/production)
- `PORT` - порт сервера (по умолчанию 3000)
- `BASE_PATH` - базовый путь приложения (по умолчанию /)
- `VITE_API_BASE_URL` - URL Laravel API (по умолчанию http://localhost:8000/api/v1)

## Структура сборки

После `npm run build:ssr`:
- `dist/client/` - клиентские файлы (HTML, JS, CSS)
- `dist/server/` - серверные модули (entry-server.js, api-ssr.js)

## Отладка

### В режиме разработки

Vite показывает детальные ошибки в консоли. Если SSR не работает:

1. Проверьте консоль сервера на наличие ошибок
2. Проверьте, что Laravel API доступен по адресу `VITE_API_BASE_URL`
3. Убедитесь, что все зависимости установлены: `npm install`

### В production

Ошибки логируются в:
- Консоль сервера
- PM2 логи: `pm2 logs react-ssr-prod`

### Типичные проблемы

1. **"Cannot find module"** - Запустите `npm install`
2. **"API Error"** - Проверьте, что Laravel API запущен и доступен
3. **Пустая страница** - Проверьте консоль браузера на ошибки гидратации
4. **Медленная загрузка** - Проверьте логи сервера, возможно проблема с загрузкой данных

## Сравнение SSR vs SPA

| Критерий | SSR | SPA |
|----------|-----|-----|
| SEO | ✅ Полный HTML на сервере | ❌ Только базовый HTML |
| Первая загрузка | ✅ Быстрее (контент сразу виден) | ❌ Медленнее (нужно загрузить JS) |
| View Source | ✅ Показывает полный контент | ❌ Показывает только `<div id="root">` |
| Без JavaScript | ✅ Работает | ❌ Не работает |
| Индексация поисковиками | ✅ Полная | ⚠️ Ограниченная |

## Дополнительные проверки

### Проверка мета-тегов для SEO

В исходном коде страницы должны быть:
- `<title>` с названием страницы
- `<meta name="description">` с описанием
- Open Graph теги (если настроены)

### Проверка производительности

1. Откройте DevTools → **Lighthouse**
2. Запустите аудит
3. **SSR должен улучшить:**
   - First Contentful Paint (FCP)
   - Largest Contentful Paint (LCP)
   - SEO Score

## Поддержка

При возникновении проблем:
1. Проверьте логи сервера
2. Проверьте консоль браузера
3. Убедитесь, что все зависимости установлены
4. Проверьте, что Laravel API доступен
