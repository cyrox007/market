# Руководство по оптимизации кэширования

## Проблемы текущей реализации

1. **Redis SCAN медленный** - при 10к товаров и множестве комбинаций фильтров SCAN может обрабатывать тысячи ключей
2. **Избыточный сброс кэша** - при изменении одного товара сбрасываются ВСЕ кэши категорий
3. **Синхронный сброс** - замедляет сохранение товаров менеджерами
4. **Нет тегирования** - невозможно эффективно группировать и сбрасывать связанные ключи
5. **Database кэш по умолчанию** - медленнее Redis для больших объемов

## Рекомендации по оптимизации

### 1. Использовать Redis с тегами кэша

```env
CACHE_STORE=redis
```

**Преимущества:**
- Быстрый доступ к данным
- Поддержка тегирования (группировка ключей)
- Эффективная инвалидация по тегам

### 2. Внедрить CacheableOptimized трейт

Трейт `CacheableOptimized` решает проблемы:
- ✅ Точечная инвалидация только связанных кэшей
- ✅ Использование тегов для группировки
- ✅ Асинхронная инвалидация через очереди
- ✅ Хранение связей вместо SCAN

### 3. Настроить асинхронную инвалидацию

```env
CACHE_ASYNC_INVALIDATION=true
```

Это позволит менеджерам сохранять товары быстрее, а инвалидация кэша будет происходить в фоне.

### 4. Оптимизировать ключи кэша

**Текущий подход:**
```
product_index:page:1:per_page:20:sort_by:created_at:...
```

**Проблема:** При изменении товара нужно найти все комбинации параметров

**Решение:** Использовать теги категорий
```
Ключ: product_index:abc123
Теги: [category_5_products, product_index_cache]
```

При изменении товара в категории 5 - просто сбрасываем тег `category_5_products`

### 5. Кэшировать мета-данные фильтров отдельно

Мета-данные фильтров (цвета, размеры, цены) меняются реже, чем списки товаров.
Кэшируйте их отдельно с большим TTL.

### 6. Использовать индексы для быстрого поиска

Для быстрого поиска товаров по категориям используйте Redis Sets:

```php
// При сохранении товара
Redis::sadd("category:{$categoryId}:products", $productId);

// При инвалидации
$productIds = Redis::smembers("category:{$categoryId}:products");
foreach ($productIds as $productId) {
    Cache::forget("product_show_{$productId}");
}
```

## Миграция на оптимизированную версию

### Шаг 1: Настроить Redis

```env
CACHE_STORE=redis
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_CACHE_DB=1
```

### Шаг 2: Обновить модели

Заменить `Cacheable` на `CacheableOptimized`:

```php
use App\Models\Traits\CacheableOptimized;

class Product extends VaniloProduct
{
    use CacheableOptimized; // вместо Cacheable
}
```

### Шаг 3: Обновить контроллеры

Использовать `cachedWithTags()` для кэширования с тегами категорий:

```php
$products = Product::cachedWithTags(
    ["category_{$categoryId}_products"],
    $cacheKey,
    $callback,
    self::CACHE_TTL
);
```

### Шаг 4: Включить асинхронную инвалидацию (опционально)

```env
CACHE_ASYNC_INVALIDATION=true
```

## Ожидаемые результаты

- **Скорость сохранения товаров:** ↑ 3-5x (за счет асинхронной инвалидации)
- **Скорость инвалидации кэша:** ↑ 10-50x (за счет тегов вместо SCAN)
- **Использование памяти:** ↓ 20-30% (за счет точечной инвалидации)
- **Нагрузка на Redis:** ↓ 40-60% (меньше операций SCAN)

## Мониторинг

Рекомендуется отслеживать:
- Количество ключей в Redis
- Время инвалидации кэша
- Hit rate кэша
- Нагрузку на Redis при сохранении товаров

## Дополнительные оптимизации

1. **Кэширование на уровне CDN** - для статических списков товаров
2. **Pre-warming кэша** - предзагрузка популярных страниц
3. **Кэширование агрегатов** - счетчики товаров, мета-данные
4. **Использование Elasticsearch** - для сложных поисковых запросов
