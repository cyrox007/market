# Управление слайдерами главной

Главная страница использует **два независимых слайдера**.

## 1. Верхний промо-блок — `placement=top`

Это блок из макета с большой промо-каруселью слева и двумя небольшими промо-карточками справа.

У верхнего блока есть дополнительное поле `slot`:

- `main` — большая карусель. Показывается и на desktop, и на mobile;
- `side` — небольшая карточка справа. На текущем mobile-макете эти карточки скрываются.

Поэтому frontend не должен определять роль элемента по порядку в массиве.

## 2. Нижний промо-баннер — `placement=bottom`

Широкий баннер-карусель после товарных блоков. На mobile остаётся отдельным широким промо-блоком, но кадрирование изображения заметно отличается от desktop.

Для этого API отдаёт отдельный набор mobile-изображений.

## Админка

Раздел: **Контент → Слайдеры главной**.

Для каждого материала можно настроить:

- блок: верхний / нижний;
- роль в верхнем блоке: основная карусель / боковая desktop-карточка;
- заголовок;
- описание;
- промо-метку или период акции;
- цвет метки: red / yellow / green;
- ссылку;
- текст CTA;
- активность;
- порядок;
- desktop-изображение;
- отдельное mobile-изображение.

Если mobile-изображение не задано, API автоматически использует desktop.

MediaLibrary-upload имеет приоритет над полями внешних URL. `image_url` и `mobile_image_url` оставлены как fallback для тестового/временного контента.

## API

### Старый совместимый вызов

```
GET /api/v1/sliders
```

Возвращает активные элементы верхнего блока `placement=top`.

### Получение конкретного блока

```
GET /api/v1/sliders?placement=top
GET /api/v1/sliders?placement=bottom
```

Верхний блок можно разделить по роли:

```
GET /api/v1/sliders?placement=top&slot=main
GET /api/v1/sliders?placement=top&slot=side
```

### Вся главная одним запросом

```
GET /api/v1/sliders/home
```

Ответ:

```json
{
  "data": {
    "top": {
      "main": [],
      "side": []
    },
    "bottom": []
  }
}
```

Этот endpoint удобнее всего для новой главной: frontend сразу получает готовые независимые массивы и не должен угадывать, какой слайд куда относится.

## Демо-данные

Добавлен идемпотентный seeder:

```bash
php artisan db:seed --class=SliderDemoSeeder
```

Он создаёт:

- 3 материала верхней основной карусели;
- 2 верхние боковые карточки;
- 5 материалов нижнего баннера.

В local/testing он также вызывается из обычного `DatabaseSeeder`.

Демо-картинки используют пути из ветки `frontend-homepage`:

- `/home/hero-1.jpg` … `hero-3.jpg`;
- `/home/promo-credit.jpg`;
- `/home/promo-showroom.jpg`;
- `/home/banner-1.jpg` … `banner-5.jpg`.

В админке есть кнопка **«Добавить демо-контент»**, которая безопасно добавляет только отсутствующие demo-записи.

## Совместимость

Старые записи таблицы `sliders` после миграции получают:

```
placement = top
slot = main
```

Поэтому существующий верхний slider API не пропадает.

Frontend-файлы в этой backend-ветке намеренно не изменяются: новую главную продолжает разрабатывать отдельная ветка `frontend-homepage`.
