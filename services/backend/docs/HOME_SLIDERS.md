# Управление слайдерами главной

В макете главной используются два управляемых карусельных блока:

1. **Главный промо-слайдер** — большой hero/promo-блок.
2. **Карусель категорий** — горизонтальный блок категорий под hero.

Эта реализация сделана только на backend/admin/API. Код главной страницы frontend в этой ветке не меняется, чтобы не конфликтовать с параллельной разработкой.

## Админка

Раздел: **Контент → Слайдеры главной**.

При создании элемента выбирается поле **Блок**:

- `home_hero` — «Главный промо-слайдер»;
- `home_categories` — «Карусель категорий».

### Главный промо-слайдер

Доступны:

- заголовок;
- описание;
- ссылка;
- текст кнопки;
- бейдж;
- активность;
- приоритет;
- основное изображение;
- отдельное мобильное изображение.

Если мобильное изображение не задано, API возвращает основное.

### Карусель категорий

Для элемента выбирается существующая корневая категория.

API автоматически использует:

- название категории;
- актуальный `full_path` категории;
- изображение категории.

В самом элементе слайдера можно загрузить собственное изображение — тогда оно переопределит изображение категории.

На странице списка есть действие **«Заполнить карусель категориями»**. Оно добавляет все отсутствующие активные корневые категории, не изменяя уже настроенные элементы.

## API

### Совместимый endpoint главного слайдера

```
GET /api/v1/sliders
```

Без параметров возвращает только `home_hero`. Это сохраняет поведение существующего frontend-кода, который уже читает `/sliders`.

Явно:

```
GET /api/v1/sliders?placement=home_hero
GET /api/v1/sliders?placement=home_categories
```

### Оба блока одним запросом

```
GET /api/v1/sliders/home
```

Формат:

```json
{
  "data": {
    "hero": [],
    "categories": []
  },
  "meta": {
    "placements": {
      "home_hero": "Главный промо-слайдер",
      "home_categories": "Карусель категорий"
    }
  }
}
```

## Поля элемента API

Основные поля:

- `id`
- `placement`
- `title`
- `description`
- `link`
- `button_text`
- `badge_text`
- `badge_link`
- `badge_icon`
- `priority`
- `image`
- `image_thumb`
- `image_hd`
- `image_fullhd`
- `image_mobile`
- `image_mobile_thumb`
- `image_mobile_hd`
- `image_mobile_fullhd`
- `category_id`
- `category` — для `home_categories`

Для `home_categories` поля `title`, `link` и изображение уже разрешаются через связанную категорию, поэтому frontend не должен отдельно загружать категорию для отображения карточки.

## Порядок

Элементы сортируются по `priority` по возрастанию. Меньшее число показывается раньше.

## Совместимость

Существующие записи таблицы `sliders` после миграции автоматически относятся к `home_hero`.

Frontend главной в этой ветке не изменяется.
