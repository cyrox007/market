# Объединение товаров OpenCart в торговые предложения (варианты)

## Как устроено у нас

- **Родительский товар:** `parent_product_id = null`, `is_variable = true` (если есть варианты).
- **Торговое предложение (вариант):** отдельная запись в `products` с `parent_product_id = id` родителя, свой `sku`, `name`, `price`, `stock`.
- В 1С-импорте модификации приходят отдельным API: по `external_id` товара запрашиваются модификации и сохраняются как варианты этого родителя.

В OpenCart в XLSX **нет отдельной сущности «модификация»**: есть только товары (Products), опции (ProductOptions) и значения опций (ProductOptionValues). Правило объединения нужно задать по этим данным.

---

## Что есть в выгрузке OpenCart

### Products
- Одна строка = один товар (`product_id`, name, model, price, quantity, categories, …).
- Каждая строка — уже отдельный SKU со своей ценой и названием.

### ProductOptions
- Связка «у какого товара какие опции»: `product_id`, `option_id`, `required`.
- Пример: товар 52 — опция 107, товар 56 — опция 15, товары 57, 58, 60 — опция 73.

### ProductOptionValues
- По каждой паре (товар, опция) перечислены **значения** опции с ценой и остатком:
  - `product_id`, `option_id`, `option_value_id`, `quantity`, `subtract`, `price`, `price_prefix` (+/-).
- Пример: у товара 52 по опции 107 может быть несколько строк (несколько `option_value_id`) — это и есть «варианты» в смысле OpenCart (один товар, несколько вариантов выбора опции с разной ценой/остатком).

### Options / OptionValues (справочники)
- Названия опций и значений: option_id → «Цвет», option_value_id → «Белый» и т.д.

---

## Варианты стратегии объединения

### 1. По опциям (ProductOptions + ProductOptionValues) — рекомендуемая основа

**Идея:** если у товара в выгрузке есть опция и у неё в ProductOptionValues есть хотя бы одно значение — считать такой товар вариативным и строить у нас «родитель + торговые предложения».

**Правило:**
- Товары **без** опций или без строк в ProductOptionValues → импортируем как **один продукт** (как сейчас).
- Товары **с** опциями и строками в ProductOptionValues:
  - **Родитель:** одна запись Product с названием/описанием из Products, `parent_product_id = null`, `is_variable = true`. Цену можно взять минимальную по вариантам или из базовой строки Products.
  - **Варианты:** по каждой строке ProductOptionValues (или по каждой комбинации опций, если опций несколько) создаём запись Product с `parent_product_id = id` родителя:
    - `name` = имя родителя + имя значения опции (из справочника OptionValues),
    - `sku` = уникальный, например `oc-{product_id}-{option_value_id}` или по model + option_value_id,
    - `price` = базовая цена из Products + `price` из ProductOptionValues (учёт `price_prefix`: `+` / `-`),
    - `stock` = `quantity` из ProductOptionValues.

**Одна опция (например, только «Цвет»):**  
число вариантов = число строк в ProductOptionValues по этому (product_id, option_id). Один вариант — одна торговая позиция.

**Несколько опций (например, «Цвет» и «Размер»):**  
варианты = декартово произведение значений опций (каждая комбинация «цвет + размер» — отдельное торговое предложение). Цена по комбинации = базовая + сумма надбавок по выбранным option_value_id (если в выгрузке так задано). Если в ProductOptionValues нет явной цены на комбинацию, а только на каждое значение опции по отдельности — суммируем надбавки по выбранным значениям.

К вариантам имеет смысл привязать атрибуты (например, «Цвет» = «Белый»), чтобы на фронте отображать выбранное торговое предложение.

---

### 2. По имени / коллекции (например, «Каролина»)

**Идея:** объединять в одну «группу» товары с общим префиксом в названии (или по полю коллекции, если появится).

- В выгрузке: «Стенка для гостиной "Каролина" : Комплектация 1», «Шкаф "Каролина" 3-х дверный…», «Стол журнальный "Каролина"» — это **разные товары**, а не варианты одного.
- У нас они логичнее как **отдельные товары** в одной категории или как «связанные» (related), а не как родитель + варианты.
- Использовать такое объединение для **торговых предложений** (вариантов одного товара) не стоит: это разные SKU с разными названиями и ценами.

Имеет смысл использовать имя/коллекцию только для связей «похожие/с этим покупают» или для фильтров, а не для `parent_product_id`.

---

### 3. По related_ids

- В Products есть поле `related_ids` — список product_id связанных товаров.
- Это аналог «с этим покупают» / «похожие», а не «варианты одного товара».
- Для торговых предложений не используем; при желании можно маппить в связь related/рекомендации.

---

## Рекомендация

- **Для торговых предложений (родитель + варианты)** использовать **только стратегию по опциям (п. 1)**:
  - Читать ProductOptions и ProductOptionValues из XLSX товаров.
  - Для каждого `product_id`, у которого есть хотя бы одна опция с хотя бы одним значением в ProductOptionValues:
    - создать одного родителя (is_variable = true);
    - создать N записей-вариантов (parent_product_id, свой sku/name/price/stock);
    - при необходимости привязать к вариантам атрибуты из справочника опций (option_id → название атрибута, option_value_id → значение).
  - Товары без опций/без значений опций оставить одиночными (как сейчас).

- **Не** объединять в варианты по общему имени («Каролина») или по related_ids — это другие сущности (коллекция, связанные товары).

Дальнейший шаг — реализовать в `OpenCartXlsxCatalogImport` режим «с вариантами»: при импорте товара проверять наличие опций/ProductOptionValues и при наличии создавать родителя + варианты вместо одной записи Product.

## Изображения и варианты (торговые предложения)

### Как устроено в OpenCart

- **Главное фото:** в таблице `oc_product` поле `image` — одно на товар (product_id).
- **Доп. фото:** таблица `oc_product_image` — строки (product_id, image, sort_order). Связь только с товаром, **не с опцией/вариантом**.
- В стандартной поставке OpenCart **нет привязки изображений к значениям опций** (к вариантам). Один товар = один набор картинок на весь товар.
- Расширения (например, Product Option Image Pro) добавляют картинки к значениям опций (option_value_id), тогда при выборе варианта на фронте может подставляться своё фото.

### Что может быть в выгрузке XLSX

1. **Только уровень товара (как сейчас):**
   - Лист **Products:** столбец `image_name` → главное фото товара.
   - Лист **AdditionalImages:** строки (product_id, image) → галерея товара.
   - У всех вариантов одного product_id получается одно и то же главное фото и галерея (мы так и делаем: родитель и варианты берут image_url и additional_image_urls из строки Products по product_id).

2. **Фото на значение опции (если выгрузка расширена):**
   - Лист **OptionValues** (файл опций): столбец `image` / `image_name` у значения опции → одно фото на все товары с этим значением (например, цвет «Белый»).
   - Лист **ProductOptionValues:** столбец `image` / `image_name` → своё фото у конкретного варианта (product_id + option_value_id).

Если в выгрузке есть такие столбцы, импорт поддерживает их: у варианта подставляется сначала фото из ProductOptionValues, при отсутствии — из OptionValues, иначе — общее фото товара из Products.
