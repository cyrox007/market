# Аудит разделов «Контент»: админка → API → React (20.11.2026)

## Решение

Этот аудит относится к `cyrox007/market` / `develop` и только к проверенному коду. **Наличие маршрута/API не означает, что компонент реально размещён на действующей странице.** Живую наполненность БД и сторонних клиентов не проверяли.

| Раздел в Filament до аудита | Что реально используется | Действие |
| --- | --- | --- |
| Слайдеры главной | `SliderController::home` → `GET /api/v1/sliders/home` → `useHomeSliders` → `PromoBoardConnected` / `PromoBannerConnected` на главной | **Оставить**. Синхронизировать SSR с новым API; тип данных `top.main`, `top.right_top`, `top.right_bottom`, `bottom`. |
| Магазины | `Store` → публичные `/api/v1/stores`, `/cities`, `/current`, `/{slug}` → активная страница `/stores` и логика самовывоза | **Оставить**. Переместить навигацию в «Доставка» рядом со «Склады». |
| О нас | `AboutPageResource` → `AboutController::show` (`/api/v1/about`) → активная страница `/about` | **Оставить** как единственный пункт редактирования. |
| Страница | `AboutPageSettingsPage` изменяет тот же `AboutPage::getInstance()`, что и ресурс «О нас». Не отдельная сущность | **Скрыть дубль из меню**, сохранив старый маршрут для прямых закладок и совместимости. |
| Подписчики | `NewsletterSubscriber` + `NewsletterController`: подписка, подписанное отписывание, обработка статуса, административная рассылка акций через очередь | **Оставить**; старый React-компонент `Newsletter` на главной выключен макетом, но сервис и админская отправка существуют. |
| Идеи для интерьера | `InteriorIdea` / `InteriorIdeaHotspot` → `/api/v1/interior-ideas`, но `Home` **не монтирует** `InteriorIdeas`; отдельного React-маршрута нет | **Скрыть из меню**, убрать бесполезный SSR-prefetch, не уничтожать таблицы/API/медиа без проверки внешних потребителей. |

## Магазины и склады

Связь `stores.warehouse_id` → `warehouses.id` не обязательна: существуют самостоятельные магазины/шоурумы без собственного склада. Для магазина со складом форма `StoreForm` предлагает выбрать действующий физический склад; `physical_site_id` определяет площадку, `shipping_location_id` — регион контактов, `pickup_enabled` — возможность выдачи заказов. **Магазин — точка контакта/выдачи, не отдельный источник остатков и не дубликат склада.** Эта структура и публичная страница магазинов сохранены без изменений; затронута только группа навигации.

## Слайдеры новой главной

Историческая связка на SSR запрашивала `/sliders` и раскладывала данные в SWR как `/api/sliders`, тогда как React теперь читает структурированный `/sliders/home` по ключу `/api/sliders/home`. Исправлено: SSR использует `/sliders/home` и тот же ключ, что промоблок/нижний баннер. Это не меняет сам API.

Для верхнего блока основная карусель и две правые карточки; для нижнего — отдельная карусель. Если верхние материалы не настроены, `PromoBoardConnected` показывает локальные DEMO-позиции; нижний баннер без материалов не показывается.

## Идеи интерьера: фактическая нагрузка и архивирование

Несмотря на отключённый React-компонент, Express SSR ещё ходил в `/interior-ideas` на каждом запросе главной, выполняя лишнее чтение и кэширование на сервере. В этой правке **автоматический запрос и гидратация удалены**, а пункт Filament скрыт.

При этом **сохранены** модели, API-маршрут, тесты API, редактор по прямой ссылке, медиа и обе исторические таблицы. Отдельный план окончательного удаления требует аудита записей и фото, проверки внешних потребителей `/api/v1/interior-ideas`, резервной копии и явного решения об удалении API-контракта. Демонстрационный `InteriorIdeasSeeder` больше не запускается автоматически вместе с основным `DatabaseSeeder`; его исходник остаётся для ручного импорта архивных демо-данных.

## О нас: дубль

`AboutPageResource` работает с singleton-моделью и отношениями `TeamMember` / `Advantage`, доступными на сайте. `AboutPageSettingsPage` редактирует тот же singleton, но имеет собственную схему и до аудита отображался под расплывчатой подписью «Страница». Второй редактор **не удалён физически**: навигация скрыта, а подпись старой страницы уточнена. В будущем можно консолидировать поля (особенно медиа и SEO) после проверки совместимости и политик доступа.

## Подписчики

Форма подписки `apps/frontend/src/pages/home/components/Newsletter.tsx` существует как архивный React-компонент, но не подключена к `home/page.tsx` и отсутствует в подвале. Подписка через публичный API остаётся возможной. В Filament есть административная операция отправки рекламных событий активным подписчикам (с ограничениями и очередью), поэтому **удаление сущности необоснованно**. Решение о возвращении формы на сайт — отдельная дизайн-задача и вопрос согласия на рекламные рассылки.

## Проверки

- Laravel: два скрытых пункта не регистрируются в навигации; «О нас», слайдеры и подписчики остаются видимыми; «Магазины» и «Склады» находятся в группе «Доставка».
- React/SSR: ключ `/api/sliders/home` заполняется структурой главных слайдеров; наследуемых ключей `/api/sliders` и `/api/interior-ideas` в SSR fallback больше нет.
- Действующие API карточки товара, складские остатки, доставка, оплата и правила цены этой правкой не затронуты.

**Статус:** безопасная корректировка админ-навигации и SSR без удаления рабочих таблиц и публичных эндпоинтов. Это **не** окончательное удаление сервиса «Идеи для интерьера».
