# «Идеи для интерьера»: проверка перед окончательным выводом из эксплуатации

Дата первичного аудита: 20.11.2026. База анализа: `cyrox007/market` / `develop` после PR #163.
**Граница:** только backend; frontend изменять запрещено.

## Подтверждённые зависимости по коду

| Подсистема | Где находится | Оценка |
| --- | --- | --- |
| Публичный контракт | `routes/api.php`, `InteriorIdeaController::index`, `Http/Resources/InteriorIdeaResource` | `GET /api/v1/interior-ideas` доступен без обязательной пользовательской авторизации; удаление сломает неизвестных внешних клиентов |

| Точки на изображении | `interior_idea_hotspots`, `InteriorIdeaHotspot.php` | Ссылки на `interior_ideas.id` и `products.id`; **FK в миграциях не создаются** |
| Публичные изображения | Spatie Media Library, коллекция `image`, варианты `thumb` / `main` | Записи `media` и оригиналы/конверсии на дисках, указанных в самой записи |
| Админка | `Filament/Resources/InteriorIdeas/`, `InteriorIdeaPolicy` | Ресурс скрыт из меню, но прямые маршруты и доступ по правам остаются |

Известные внутри репозитория потребители: архивный React-компонент (не смонтирован на главной), публичный API-контракт, административный ресурс, API-тесты, модель товара при удалении, старый ручной seeder. Отсутствие остальных клиентов **не доказано** только анализом исходников.

## Безопасная инвентаризация на целевом окружении

Создана команда:

```bash
cd services/backend
php artisan content:audit-interior-ideas
php artisan content:audit-interior-ideas --verify-files --file-limit=100
```

Команда выполняет только чтение БД и, при `--verify-files`, выборочную проверку существования файлов на указанных дисках. Она **не** изменяет таблицы, файлы, права, кэш и API. Никаких автоматических очисток.

JSON-результат включает:
- общее и активное количество идей;
- количество точек и ссылок на отсутствующие идеи/товары;
- количество связанных Spatie Media, сиротских media-записей, разбивку по дискам;
- ограниченную выборку проверки оригиналов и отмеченных сгенерированными вариантов `thumb` / `main`;
- принудительные `external_api_consumers_verified: false` и `safe_to_delete: false`.

**Важно:** `--file-limit` ограничивает выборку для физической проверки (1–1000 записей), не подсчёт метаданных БД. Даже успешная выборка не доказывает полноту наличия всех файлов. При отсутствии необходимых таблиц команда сообщает `missing_tables` и завершается с ошибкой. Не выполняйте ручной `InteriorIdeasSeeder` во время аудита: он может создавать записи/товары.

## Что нельзя проверить из GitHub

1. Наличие и количество записей/медиа на боевом сервере. Команду необходимо запустить **в целевом окружении**; результаты из тестовой SQLite БД не подтверждают продакшен.
2. Фактические обращения внешних приложений к `GET /api/v1/interior-ideas`. Просмотреть реальные HTTP access-логи reverse proxy/API минимум за согласованный период (рекомендуется 30–90 дней), учитывая оба варианта пути, кэши и прокси. Отдельно проверить мобильные клиенты, CMS, партнёрские интеграции, SEO-сканеры и сохранённые ссылки. Отсутствие хитов не является доказательством отсутствия редких клиентов.
3. Наличие резервной копии исходных изображений на всех используемых дисках и возможность её восстановления.
4. Где размещены окружения с другими версиями backend, зависящими от схемы БД.

## Критерии принятия решения

**По умолчанию удаление блокируется.** Для физического удаления необходимы:
- согласованный отказ от публичного API-контракта (с уведомлением потребителей, если они существуют);
- инвентаризация на всех целевых окружениях и бэкап БД/медиа с проверенной процедурой восстановления;
- устранённые осиротевшие ссылки и подтверждённая судьба исторических изображений;
- удаление зависимости `Product::deleting` от архивной таблицы **вместе** с миграцией, API/моделями/правами/тестами (не раньше);
- отдельный PR с тестами миграций, API и удаления товаров, оставленный открытым до проверки и явного разрешения.

В данном PR никаких данных и контрактов не удаляется. **Этот этап завершает техническую инвентаризацию и предоставляет проверочный инструмент, но не является подтверждением безопасного физического удаления.**

## Тестирование

```bash
cd services/backend
php artisan test --filter='AuditInteriorIdeasRetirementTest|InteriorIdeaControllerTest|RetiredContentDashboardTest'
```

Проверяется корректность отчёта, обнаружение «осиротевших» точек, выборочный контроль медиа и сохранение существующего публичного API (отдельными тестами). Поскольку реальные внешние клиенты и данные недоступны из CI, позитивные автотесты не снимают ограничений выше.
