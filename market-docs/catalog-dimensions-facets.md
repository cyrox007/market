# Каталог: габариты, совместимые варианты и счётчики

Ветка `feature/catalog-dimensions-variant-facets`, поверх `feature/catalog-api-quick-fixes`. Только Laravel/API и Filament; без React, миграций данных и выкладки на сервер.

## Габариты в миллиметрах

`GET /api/v1/products?category_slug=divany&width_min=1000&width_max=2500&depth_max=1000&height_max=1200`

Параметры: `width_min/max`, `depth_min/max`, `height_min/max`. Все границы включительны, от 0 до 1 000 000 мм; если заданы обе, max должен быть не меньше min. Некорректный ввод — 422 с `message` и `errors`. Эти же параметры поддерживает `/api/v1/products/count`.

Источники — характеристики `sirina-mm`, `glubina-mm`, `vysota-mm`. Значение справочника или своё числовое значение; десятичный разделитель точка либо запятая. Пустые, нулевые, отрицательные и текстовые значения (например «1200 мм») не участвуют в диапазонах. Поля `products.width/length/height` не подмешиваются: это отдельные физические/логистические данные. `size` по-прежнему торговый размер, не габариты.

```json
{"meta":{"filters":{"facet_mode":"excluding_self","dimensions":{
  "width":{"min":1200,"max":2400,"unit":"mm"},
  "depth":{"min":null,"max":null,"unit":"mm"},
  "height":{"min":800,"max":1100,"unit":"mm"}
}}}}
```

Нет числовых данных — `min/max: null`, не выдуманный нулевой размер. Размерные характеристики представлены диапазонами, не дублируются в `attributes`.

## Один подходящий вариант

Цена, акция, цвет, торговый размер, прочие характеристики и габариты должны одновременно соответствовать **одному активному SKU**. Между значениями одной характеристики OR, между разными характеристиками AND. Родитель с красным маленьким и синим большим вариантом не подходит запросу «красный большой».

Общие характеристики наследуются от родителя, если у SKU нет своего значения этой характеристики. Свой размер SKU заменяет родительский. Характеристики вариаций (в том числе color/size) не наследуют родительский список доступных опций. Неактивный SKU не влияет на выдачу и счётчики. Родительская карточка возвращается один раз.

Фильтрация не выбирает SKU за покупателя: карточка остаётся родительской, её существующие поля цены/вариантов не подменяются выбранным предложением. Конкретный вариант нужно выбрать перед добавлением в корзину.

## Смысл фасетов

`facet_mode: excluding_self`: каждый фасет учитывает все **остальные** пользовательские фильтры, исключая собственный выбор целиком. Для цвета убираются `colors` и `attr_color`; для размеров — `sizes` и `attr_size`; для ширины — обе границы ширины; для цены — обе границы цены. Область категории/комнаты, поиск, региональная видимость остаются. Обязательные ограничения комнаты никогда не исключаются.

`values[].count` — количество уникальных родительских карточек, имеющих подходящий SKU с данным значением; не количество SKU и не остаток. При нескольких выбранных значениях это размер выдачи при выборе одного данного значения, **не** прирост от добавления галочки к уже выбранным. Значения с нулевым результатом не возвращаются; клиент может сохранять выбранные недоступные значения из собственного состояния.

`has_on_sale` — есть ли акционные SKU при остальных ограничениях, без пользовательского `on_sale`. Диапазоны цены/габаритов вычисляются по подходящим SKU, исключая собственные пользовательские границы. Формат одинаков для категорий, нескольких категорий и комнат. Без области категории/комнаты `meta.filters` остаётся null.

Legacy `manufacturer_id/manufacturer_slug` остаются ограничением области: новый рекомендованный многозначный фасет производителя — `attr_proizvoditel`. Цены/акции здесь базовые сохранённые; персональные и региональные скидки не пересчитываются для фильтра.

## Админка

Товар → «Характеристики»: задавайте габариты числом в мм, без единиц. Для общего размера заполните родителя; для отличающегося предложения откройте редактирование самого предложения и заполните его характеристику. Цвет/торговый размер задаются в торговых предложениях. В справочнике характеристик сохраните системные slug; они перечислены в подсказке.

После сохранения характеристик кеш каталога обновляется **после записи pivot**, включая случаи, когда поля самого товара не изменились. Цена/старая цена, состояние SKU, одобрение отзывов и настройка фильтруемости используют существующие формы и модельные события. Переноса данных между справочниками производителей не выполняется.

Это уточняет и заменяет разделы об ограничениях совместимости SKU и старом смысле фасетов в `catalog-quick-fixes.md`.

## Проверки

`CatalogDimensionsFacetsTest`: диапазоны/count, разные SKU, цена/акция/габариты совместно с цветом, исключение неактивных SKU, самoисключающиеся фасеты, уникальные карточки, наследование/переопределение, числовые custom_value, ошибки границ, кеш после сохранения из админки, обязательные фильтры комнат.
