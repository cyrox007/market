# Одноразовый перенос каталога — локальный анализ и применение таблиц

Раздел: `/admin_sv/catalog-transfer`, группа «Интеграции», право `viewAny catalog_sync`.
React и боевые данные не затрагиваются. По умолчанию форма запускает локальный перенос; для анализа без изменений включите «Только проверить». Перенос создаёт/обновляет товары из таблиц, затем дополняет характеристики и складские остатки из API. Таблица — источник истины. Независимо от доступности API переносится галерея старого сайта; только однозначные структурные совпадения категорий добавляются автоматически.

## Как пользоваться

1. Загрузить до 12 файлов XLS/XLSX (до 12 МиБ каждый; стандартный лимит Livewire).
2. Для каждого файла указать название листа (пусто — первый), строку заголовка, буквы колонок кода 1С, ID OpenCart и цены. Цена и ID могут быть пустыми. При необходимости указать колонку пути изображения; несколько путей разделяются точкой с запятой или переносом строки. Необязательная колонка категорий содержит пути OpenCart (`73_111`, несколько через запятую/точку с запятой, до 20 на товар); они позволяют читать карточку с категорией в хлебных крошках.
3. Нажать «Запустить перенос товаров» либо включить «Только проверить» и запустить проверку. Стандартные заголовки OpenCart распознаются автоматически. Можно закрыть вкладку. Приостановка сохраняет текущую порцию, продолжение использует контрольные точки.
4. Проверить совпадения, конфликты, ошибки и данные источников. Поиск журнала — по коду 1С; результаты постраничные, события сохраняются отдельно.
5. Нажать «Применить таблицу локально». Создаётся отдельный запуск, прежний анализ сохраняется. Доступны только локальная среда и пользователи с правами создания/редактирования товаров. «Повторить дополнение» не создаёт товар заново и не применяет повторно таблицу.

Файлы с разной структурой настраиваются независимо. Для нескольких листов одной книги загрузите книгу отдельно для каждого нужного листа.

## Локальный обработчик

Применить только миграцию этой функции к локальной БД сайта, затем запустить отдельный процесс:

```powershell
php artisan migrate --path=database/migrations/2026_10_16_140000_create_catalog_transfer_tables.php
php artisan migrate --path=database/migrations/2026_10_16_150000_add_catalog_transfer_application.php
php artisan migrate --path=database/migrations/2026_10_16_160000_add_catalog_transfer_assets.php
php artisan migrate --path=database/migrations/2026_10_16_170000_create_catalog_transfer_settings.php
php -d memory_limit=512M artisan queue:work database --queue=catalog-transfer --timeout=120 --memory=512 --sleep=1
```

Очередь явно `database/catalog-transfer`, даже если основной драйвер очереди — sync. Для постоянной работы процесс нужно держать запущенным/под супервизором. UI показывает время последней активности и предупреждает о зависшей обработке; он не обещает работу без запущенного worker.

## Правила и безопасность

- Код 1С — подтверждённый столбец `sku` таблицы. Поиск на сайте: `products.external_id` или точное `products.sku`, включая предложения. Если они указывают на разные товары — конфликт. Для старого OpenCart-импорта допускается замена `external_id`, равного старому `product_id`, на код 1С. Другой существующий код не перезаписывается. Название для сопоставления не используется.
- Данные разных файлов объединяются по коду 1С; несовпадающие цены или старые ID требуют ручного решения. Повторные чтения не создают дублей строк. Каждая исходная строка сохраняется с файлом/листом/номером.
- Чтение по 100 строк с контрольной точкой. Не более 100 000 строк на лист; формулы в ключевых колонках отклоняются (сохраните значения). Для кодов сохраняется числовая маска ведущих нулей; уже утраченные Excel нули восстановить невозможно.
- В стандартном экспорте OpenCart дополнительные изображения читаются с `AdditionalImages` и связываются только по `product_id`. Посторонние строки вспомогательного листа не присоединяются. Значение категории `0` считается служебным отсутствием категории. Акции/групповые и опционные цены других листов не подменяют основную цену `Products.price`.
- Старые карточки читаются по целочисленному ID только с `https://svetofor-mebel.ru`. Поддерживается обычная служебная cookie Beget для публичной страницы, без исполнения JavaScript. Изображения — только галерея `.thumbnails` внутри `#content` либо `.content-container` старой темы; соседние товары исключаются. URL ограничены `/image/` того же HTTPS-хоста, без обходов пути. Оригинальный `catalog/...` из таблицы сохраняется как `/image/catalog/...`; из кешированного URL оригинал не угадывается.
- Для применения объединяются главное изображение таблицы, `AdditionalImages` и **вся галерея публичной карточки**, даже если таблица уже содержит изображения. Переносится один файл за шаг; источник и SHA-256 сохраняются в медиа для повторного запуска без дублей. При наличии главного изображения оно сохраняется, новые файлы добавляются в галерею. У нового товара первый успешно загруженный файл становится главным. Старые файлы не удаляются.
- Навигация старого сайта помогает развернуть ID категории таблицы в путь родителей. Привязка разрешена только при одном точном совпадении названий всей цепочки; существующие связи не удаляются. Неоднозначные/неполные цепочки и ошибки изображений остаются в `assets_result.warnings`, видимом в журнале строки. Завершение проверки не означает отсутствия предупреждений.
- Хлебные крошки — не полный список категорий товара. Предлагаются только точные совпадения названий **и всей цепочки родителей** в новой таксономии. Похожие названия, отсутствующие и неоднозначные совпадения требуют ручной проверки. Полный обход категорий пока не включён.
- API читается через `/api/v1/integration/1c/v2/cache/products/{code}`, `/characteristics`, `/stocks`, в том числе в режиме проверки. Настройки существующей интеграции `catalog_import.config.svetofor_1c`. Токен для публичного чтения не обязателен; при необходимости он сохраняется зашифрованным в настройках переноса. При HTTP вместо HTTPS возвращается `https_required`; для api.svetofor-mebel.ru автоматически используется HTTPS. Код в ответе API обязательно проверяется.
- При локальном применении отсутствующий товар создаётся из таблицы (нужны код, название и цена). Заполненные название, цена, описание, производитель, модель, габариты и SEO принадлежат таблице; пустые поля не стирают существующие значения. Старый `quantity` не импортируется как достоверный складской остаток: новый товар начинает с нуля.
- Сначала применяются все валидные строки таблиц, затем API. Контрольные точки товара и дополнения независимы; ошибка API не откатывает товар. Статус `applied_waiting` доступен для повторного дополнения после настройки доступа. Пустые коды и конфликты не создают товары.
- Остатки применяются существующим `ApplyOneCStockSnapshotAction`: неизвестный склад сначала создаётся по ID 1С, затем записывается остаток; отсутствующие в успешном полном снимке старые остатки обнуляются. Некорректный ответ или ошибка запроса не обнуляют остатки. Цена API никогда не применяется этим механизмом.
- Защита `TransferTableAuthority` также действует для прежнего `Svetofor1CCatalogImport`: синхронизация цен, описания и защищённых характеристик не перезаписывает заполненные поля применённых таблиц. Таблицы/контрольные точки переноса нужно сохранять, пока этот приоритет нужен.
- Один обработчик одновременно, ограничение запросов по хосту, тайм-ауты, запрет редиректов и ограничение размера ответа. 429 откладывает продолжение на `Retry-After + 1`, временные ошибки повторяются до 5 раз; затем строка отмечается ошибкой, остальные продолжаются. Успешные старые карточки кешируются на час.
- Таблицы `catalog_transfer_*` сохраняют исходники, результаты, прогресс, журнал и контрольные точки применения. Анализ остаётся полностью read-only по отношению к каталогу.
- Ответ API сохраняется в отчёте строки: склады, количества, характеристики и исходные поля. Получение ответа и применение в карточке различаются по `api_applied_at`. По категориям сохраняются названия старой цепочки, кандидаты нового сайта и факт назначения; предупреждения не скрываются за статусом завершения. Строки без sku пропускаются, а не считаются ошибками.
- Автообновляется только отдельный Livewire-блок прогресса и только в состоянии `running`. Форма, список результатов и раскрытые подробности не перерисовываются от таймера. Журнал API содержит URL без токенов и HTTP-статус фактического запроса.

## Что уточнить на реальных файлах

Полный источник принадлежности категориям, если их нет в таблице/навигации; ручное разрешение неоднозначных цепочек; правила назначения изображений вариантам. По умолчанию существующие изображения и категории сохраняются, недостающие добавляются. Источник цены и заполненных полей уже согласован: таблица.

Для стандартной таблицы OpenCart с подтверждёнными кодами 1С в `sku` можно поставить анализ в очередь без браузера:

```powershell
php artisan catalog-transfer:analyze "C:/Users/User/Downloads/Гостиные со старого.xlsx"
# Явно применить локально:
php artisan catalog-transfer:analyze "C:/Users/User/Downloads/Гостиные со старого.xlsx" --apply
```

По умолчанию: лист Products, код 1С D, старый ID A, цена P, изображение N, категории C. В других файлах параметры задаются явно.
