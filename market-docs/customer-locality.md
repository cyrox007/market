# Населённый пункт покупателя: КЛАДР + собственные координаты

> Устаревший прототип. React-изменения откачены, отдельный SQLite-справочник и Python-скрипты
> удалены из рабочего решения. Не использовать инструкции ниже для новой разработки.
> Актуальный контракт: [ГАР, геолокация и адреса](address-geolocation-contract.md).

Ветка `feature/customer-locality`. Изменения сделаны в основной локальной копии сайта,
не в копии репозитория. Боевую базу и адресный API эти скрипты не изменяют.

## Работа на сайте

- Геолокация браузера (разрешение пользователя, HTTPS) передаёт координаты только
  Laravel endpoint `POST /api/v1/localities/detect`. Nominatim и IP API для нового
  выбора не вызываются.
- Бэкенд возвращает до пяти сопоставленных пунктов в радиусе 25 км, по расстоянию
  до центра. Это предложения для подтверждения, НЕ определение административной
  границы. За пределами покрытия не подставляется город по умолчанию.
- Ручной поиск: название по всей России либо с ограничением на регион. Все актуальные
  населённые пункты КЛАДР доступны, даже если координаты не сопоставились.
- Подтверждение получает каноническую запись через GET /api/v1/localities/{code}.
  Сохраняется externalId КЛАДР в localStorage selected_customer_locality.
  Шапка показывает населённый пункт, а не складскую область. После перезагрузки
  запись повторно проверяется сервером; ошибка сети не стирает последнее подтверждение.
- ShippingLocation остаётся отдельной сущностью. Для старого расчёта доставки используется
  единственная активная локация с соответствующим кодом КЛАДР/кодом региона.
  При отсутствии кода возможен только однозначный регион с тем же нормализованным
  названием. Город не сопоставляется по подстроке. Если связи нет, старый выбранный
  регион сбрасывается; никакая произвольная локация вместо него не назначается.

## Подготовка данных

Python 3.12+, пакет osmium==4.3.1 нужны только при извлечении OSM, НЕ на сервере сайта.

```powershell
python -m venv storage/geodata/tools
storage/geodata/tools/Scripts/python.exe -m pip install osmium==4.3.1
storage/geodata/tools/Scripts/python.exe scripts/geodata/extract_places.py storage/geodata/osm/russia-261006.osm.pbf storage/geodata/osm/places.sqlite
node scripts/geodata/export_kladr.cjs C:/OSPanel/home/api.local storage/geodata/kladr.json
storage/geodata/tools/Scripts/python.exe scripts/geodata/build_localities.py storage/geodata/kladr.json storage/geodata/osm/places.sqlite storage/geodata/customer-localities.sqlite
```

Экспорт читает regions и localities через имеющийся Prisma-клиент API, без записей
в БД. Исходные адреса/здания не выгружаются. Скрипты отказываются перезаписывать
имеющиеся файлы: новую версию собирайте под новым именем. SQLite проверяется
integrity_check и публикуется переименованием только после успешного окончания.

Снимок от 08.10.2026: 151 669 OSM settlement nodes; 160 309 актуальных 13-значных
записей КЛАДР; 52 726 сопоставлений. Связь создаётся только при уникальном
нормализованном названии внутри одного региона на обеих сторонах. Неоднозначные
названия, отсутствующие региональные теги OSM, несовпадения классификаторов
оставлены без координат. Источник — Geofabrik Russia 06.10.2026 / OSM contributors.
Исходные и производные данные не включаются в Git и не публикуются как frontend assets.
Атрибуция OSM присутствует в окне и API. При распространении производного справочника
нужно соблюдать лицензию исходных данных ODbL.

## Перенос на сервер

На сервере нужны PHP pdo_sqlite и один файл `customer-localities.sqlite` (~40 МиБ),
а не исходный PBF 4 ГБ. Не импортировать его в MySQL и не запускать Prisma-миграции.

1. Передать снимок в непубличный каталог под новым версионным именем.
2. Сравнить SHA-256 локального и переданного файла:
   `Get-FileHash <file> -Algorithm SHA256` / `sha256sum <file>`.
3. Задать в Laravel .env `CUSTOMER_LOCALITIES_DATABASE=/absolute/path/to/file.sqlite`.
   PHP-процессу достаточно прав чтения. Радиус: `CUSTOMER_LOCALITIES_RADIUS_KM=25`.
4. Обновить код/собрать frontend, обновить Laravel config cache принятой командой
   деплоя. Старый снимок оставить для отката, менять путь только после проверки.
5. Проверить /api/v1/localities?q=Лип и POST /api/v1/localities/detect с
   latitude=52.605, longitude=39.596. Первый кандидат — 4800000100000, Липецк.

Локально путь настроен по умолчанию на <repository>/storage/geodata/customer-localities.sqlite.
На http://svetofor.local ручной выбор работает; геолокацию браузер обычно блокирует,
поэтому для неё нужен локальный HTTPS.

## Граница этой реализации

Готовы собственная геолокация с подтверждением, ручной выбор КЛАДР, сохранение
и мост к существующим региональным настройкам. Это НЕ новая сортировка каталога
по удалённости складов: текущий FulfillmentSourceResolver всё ещё использует
складские зоны/сроки/стоимость. Дистанционное ранжирование до пагинации, полный
SSR-контекст населённого пункта и переработка checkout остаются отдельной задачей.
Непривязанная область не означает бесплатную или доступную доставку.
