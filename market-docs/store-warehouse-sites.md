# Тестовая схема: магазин, склад и общий адрес

Ветка `feature/store-warehouse-sites`. Основана на доработке адресов складов из PR #75; на прод не выкладывается автоматически. React не меняется.

## Что настраивает оператор

| Ситуация | Магазин | Склад / источник |
|---|---|---|
| Магазин с остатками, например Чаплыгин | «Да — товары учитываются на складе этого магазина»; выбрать склад по ID 1С | Действующий физический склад с фактическими остатками; та же площадка |
| Головной офис, магазин и склад в одном здании | Выбрать склад и ту же площадку | Общая площадка, при необходимости отдельные координаты въезда |
| Выставочный зал без своих остатков | «Нет — только магазин / выставочный зал»; выбрать адрес | Не нужен |
| Отдельный склад | Не нужен | Физический склад и площадка |
| Виртуальная фабрика / поставщик | Не связывать как склад магазина | Источник под заказ; адрес и координаты только если известна фактическая отгрузка |

## Чаплыгин: настройка по шагам

1. Откройте **Доставка → Склады**. Найдите склад по `stockId` из 1С. Не создавайте второй склад для тех же остатков.
2. В адресе выберите **Адрес площадки**. Если нужного места нет, нажмите **+**: название → населённый пункт → улица → здание. Один выбор работает с ГАР и КЛАДР. Координаты вводятся парой; не подставляем центр города вместо реальной точки.
3. Сохраните склад. Цены, сроки и зоны настраиваются в его существующих профилях доставки.
4. Откройте **Магазины**. Выберите «Да — товары учитываются на складе этого магазина» и уже настроенный склад. Площадка подставится из склада.
5. Заполните название, телефон, график, изображение. Сохраните.

Если магазина с остатками ещё нет в 1С, создание физического склада остаётся отдельным явным шагом. Связь магазина никогда не создаёт новый `stockId` автоматически.

Площадку можно изменить карандашом прямо в выборе адреса. Подсказка предупреждает: изменение общее для всех связанных магазинов и складов. При смене здания сбрасываются старые отдельные координаты отгрузки. Координаты въезда склада можно задать отдельно — они имеют приоритет над точкой площадки.

## Хранение и совместимость

- `physical_sites`: проверенный общий адрес, идентификаторы ГАР/КЛАДР, снимок иерархии, координаты.
- `stores.physical_site_id`: публичный адрес магазина; `stores.warehouse_id`: чей учёт остатков используется.
- `warehouses.physical_site_id`: общая площадка. Старый адрес склада сохранён как совместимый снимок; отдельный въезд — существующие latitude/longitude склада.
- Остатки остаются только в `product_warehouse_stocks`. Импорт 1С по прежнему `external_id` сохраняет связи; тест подтверждает отсутствие дублирования.
- Старые магазины без площадки можно редактировать. Миграция не сопоставляет их автоматически по названиям/адресам и не трогает существующие остатки.
- Нельзя незаметно перенести склад связанного магазина на другую площадку или сделать его виртуальной фабрикой: сначала изменить связь в магазине.
- Удаление используемой площадки/склада блокируется внешними ключами, не каскадно удаляет магазины.

## API для будущего фронтенда

Существующие `/api/v1/stores` и `/api/v1/stores/{slug}` сохраняют прежние поля. Дополнительно: `physical_site_id`, `warehouse_id`, `has_own_stock`, `gar_guid`, `kladr_code`. Координаты/адрес берутся из площадки, если она задана, иначе из старых полей магазина. `has_own_stock` означает настроенный действующий источник фактических остатков, не положительное количество каждого товара.

Это не реализация самовывоза, бронирования и маршрутизации. Существующая бизнес-локация магазина оставлена для правил корзины и не используется как идентификатор адреса. Расстояние — по прямой; источник отгрузки сначала фильтруется по наличию и зоне доставки.

## Локальная проверка

Миграция: `2026_10_09_140000_link_stores_and_warehouses_to_sites` (зависит от миграции адресов склада из PR #75). Применять только выбранную миграцию в тестовом окружении; для боевого переноса сначала резервная копия и ревью.

Проверены формы создания магазина и склада с общей площадкой, старые магазины, запрет фабрики и разных площадок, приоритет въезда, изменение общей точки, синхронизация 1С и JSON магазина.
