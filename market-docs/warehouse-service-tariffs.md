# Тарифы услуг складского профиля: совместимый переход

## Режимы
- `service_tariffs = null`: прежний расчёт через `services_location_id`, с наследованием старых цен. Ничего автоматически не переключается.
- JSON, включая `[]`: явно включённые новые тарифы. Старые цены не подмешиваются.
- Переключатель «Использовать новые тарифы этого профиля» в профиле склада управляет режимом. Обычное сохранение старого профиля оставляет null. Выключение возвращает прежний расчёт; прежняя ссылка сохраняется.
- Старые API, контроллеры, адресные мосты и редакторы локаций/региональных методов доставки сохранены. Фронт не изменён.

## Правила новых тарифов
Сборка — фиксированная цена за заказ; обязательная добавляется сервером. Пустая цена означает недоступность, ноль — бесплатно.
Подъём: строка этажа задаёт полную цену, а не множитель. Иначе применяется базовая цена. Для типа elevator специальная цена лифта приоритетнее.
Дополнительные услуги — только активные с фиксированной ценой. Клиент не задаёт цены. Дубли услуг, отрицательные цены и повторяющиеся этажи отклоняются.
Срок сборки хранится отдельно от перевозки. Бесплатная перевозка не обнуляет сборку и подъём.
Гибридное покрытие требует совпадения территории И радиуса; у склада используется первый подходящий профиль по приоритету.

## Контракт
POST /api/v1/shipping/quote сохраняет параметры requires_assembly, delivery_handling_type_id, delivery_floor, additional_services: [{id}].
service_options в выбранном варианте и options содержит assembly, handling, additional для нового режима. Для старого режима service_options = null — это не обещание отсутствия услуг.
Цены рассчитывает сервер. Неизвестные услуги не становятся бесплатными. Изменение профиля меняет fingerprint расчёта.
Реализация будущего интерфейса выбора новых услуг остаётся отдельной задачей.

## Порядок переноса
1. Применить миграцию добавления nullable JSON. Сама миграция цены не меняет.
2. Выполнить read-only команду `php artisan shipping:audit-service-tariffs`: список профилей, режим, старая локация, отсутствующие ссылки.
3. Для профиля выписать эффективные прежние цены сборки, подъёма по этажам, лифта и дополнительных услуг, включая наследование.
4. Заполнить новые тарифы и сверить одинаковые сценарии: без услуг, сборка, этажи, лифт, дополнительные услуги, бесплатная доставка.
5. Только после сверки сохранить включённый переключатель. Автоматической конвертации нет: старые правила не всегда эквивалентны новым.
6. Проверить оформление и повторную проверку цены заказа. При расхождении выключить переключатель.
7. Старые API и редакторы удалять только отдельным изменением после миграции всех клиентов.

На сервер эта доработка автоматически не выкладывается. Заказы и адресные снимки не переписываются.
