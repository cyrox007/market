# Услуги складского профиля без старых локаций

Первый пакет вывода легаси, 21.10.2026. Ветка `feature/warehouse-service-tariffs`.
Миграция `2026_10_21_120000_add_service_tariffs_to_warehouse_delivery_profiles.php`
добавляет nullable JSON `service_tariffs`. Старые таблицы и снимки заказов не удаляет.

## Настройка

Склады → нужный склад → Зоны, цены и сроки → профиль → «Услуги этого профиля».
Там задаются обязательность/цена/срок сборки, типы подъёма, базовая цена,
фиксированная цена для типа `elevator`, полная цена для конкретных этажей и
фиксированные цены дополнительных услуг. Это не цена за каждый этаж:
для указанного этажа применяется полная цена строки, иначе базовая цена.
Глобально отключённые услуги/типы недоступны независимо от сохранённого тарифа.
Незаполненная цена означает недоступность, нулевая — явно бесплатную услугу.

Справочники `DeliveryHandlingType` и `AdditionalService` сохраняются. Складской
расчёт больше не читает `ShippingLocation`, наследуемые цены, старые pivot-таблицы
услуг и `DeliveryHandlingProvider`. В форме профиля убраны выбор старой локации
тарифов и редактор старых привязок покрытия. Старый fallback покрытия пока остаётся
в других компонентах и относится к следующему пакету.

## API для фронта

`POST /api/v1/shipping/quote` сохраняет существующие параметры выбора услуг:
`requires_assembly`, `delivery_handling_type_id`, `delivery_floor`,
`additional_services: [{id}]`. Цены передавать нельзя.

В `selected` и каждом элементе `options` добавлено `service_options`:

```json
{
  "assembly": {"available": true, "required": false, "price": 400, "days": 2},
  "handling": [{"id": 1, "name": "Подъём", "code": "stairs", "requires_floor": true,
    "max_floor": 10, "requires_elevator": false, "base_price": 100,
    "floor_prices": [{"floor": 3, "price": 450}]}],
  "additional": [{"id": 1, "name": "Упаковка", "price": 300, "price_type": "fixed"}]
}
```

Использовать варианты услуг именно выбранного профиля; при смене склада сверять
выбор с его `service_options` и пересчитывать quote. При недоступной услуге сервер
может вернуть 422 — не подменять её бесплатной. Snapshot заказа содержит уже
рассчитанные суммы, а не ссылку на старую тарифную локацию. Цена услуг входит
в атрибуты профиля и его fingerprint для проверки изменения перед резервированием.

## Развёртывание и ограничения

Этот пакет пока реализован и проверен локально; миграция на боевом не выполнялась.
Перед выкладкой проверить фактическое число профилей и старые `services_location_id`.
Если есть ранее настроенные профили, сначала явно перенести эффективные тарифы
в новый JSON и сверить суммы. Автоматического наследования или молчаливой конвертации
нет. Профиль с неперенесённой старой ссылкой и null JSON блокирует новый расчёт,
чтобы не потерять обязательные услуги. Исходная ссылка остаётся в БД как архив,
но Eloquent-отношение `servicesLocation` и её редактор удалены.

Обычный пустой новый профиль услуг не блокирует транспорт, но выбрать неописанную
сборку/подъём/услугу нельзя. На боевом складе реальные адреса и тарифы задаёт оператор
после появления нужных домов в справочнике; этот пакет не создаёт их автоматически.

Покрытие, региональные цены, оплата, старый checkout и исторические операции
ещё требуют отдельных пакетов из аудита `shipping-legacy-audit-20261021.md`.
