# Устойчивость адресного справочника при авариях upstream

## Цель и граница доверия

Сайт использует внешний `api.svetofor-mebel.ru/api/v2/address`. Если upstream недоступен
(HTTP 5xx / timeout / невалидный JSON), покупатель должен по возможности
продолжить **поиск** в уже известных городах, улицах и домах.

Новый механизм — `AddressDirectoryClient::cachedList()` — это два независимых слоя:

- **Fresh:** недавний результат внешнего API; при его наличии новых сетевых запросов нет.
- **Last good:** последний успешный НЕПУСТОЙ список, хранимый дольше. Только если
  upstream фактически не ответил, из него возвращаются данные для навигации.

На валидную ошибку 400/404/422 неверного родителя адреса старые данные НЕ подставляются.
После первого сбоя по уже кэшированному ключу действует 30-секундная пауза перед новой
проверкой внешнего API: последующие запросы мгновенно получают last-good, а не ждут
трёхсекундного таймаута каждый раз.
Пустые списки домов не сохраняются как last-good, потому что база домов ещё пополняется.
Вызовы `status` и `nearby` не кэшируются — особенно точные координаты посетителя.

**Не использовать устаревшие списки для окончательной проверки адреса/оплаты.**
`hierarchy(externalId)` использует только действующий основной кэш с
`ADDRESS_DIRECTORY_CACHE_TTL`, без last-good fallback: после истечения TTL и
аварии upstream разрешение нового адреса в `DeliveryAddressResolver` выдаст
ошибку, и `shipping/quote` и `orders` не подтвердят неподтверждённую доставку.
Сам расчёт доставки, тарифы, склады и суммы денег не кэшируются этой функцией.

## Таймауты и сроки кэша

| Тип списка | Свежий TTL | Last-good при аварии |
| --- | ---: | ---: |
| `regions` | 24 часа | до 7 суток |
| `localities` | 1 час | до 7 суток |
| `streets` | 30 минут | до 7 суток |
| `buildings` | 5 минут | до 7 суток, только непустые |
| Любой поиск с `q` | не более 5 минут | до 24 часов |
| `hierarchy` | 24 часа (прежнее поведение) | **нет** |
| `status`, `nearby` | нет | **нет** |

Все значения настраиваются через `config/address_directory.php` и переменные среды:

```env
ADDRESS_DIRECTORY_REGIONS_TTL=86400
ADDRESS_DIRECTORY_LOCALITIES_TTL=3600
ADDRESS_DIRECTORY_STREETS_TTL=1800
ADDRESS_DIRECTORY_BUILDINGS_TTL=300
ADDRESS_DIRECTORY_SEARCH_TTL=300
ADDRESS_DIRECTORY_STALE_ENABLED=true
ADDRESS_DIRECTORY_STALE_TTL=604800
ADDRESS_DIRECTORY_SEARCH_STALE_TTL=86400
ADDRESS_DIRECTORY_FAILURE_COOLDOWN=30
```

Публичный JSON для `GET /api/v1/address-directory/{level}` не изменяется:
`{ "data": [...] }`. Добавлен ответный заголовок
`X-Address-Directory-Cache: live|fresh|stale`.
При `stale` также: `X-Address-Directory-Cache-Age: <seconds>`.
Для ответов `stale` заголовок `Cache-Control: private, no-store` запрещает
клиенту/прокси закреплять устаревшие данные. При `live` и `fresh` прежнее
публичное ETag-кэширование `/regions` продолжает работать.

## Предпрогрев часто запрашиваемых городов

Перед возможным отключением upstream или после нового деплоя:

```bash
php artisan address-directory:warm-cache --dry-run
php artisan address-directory:warm-cache
```

По умолчанию прогреваются регионы. Часто запрашиваемые города оператор указывает
в `.env`, исходя из реальных запросов посетителей, а не предполагаемого топа:

```env
ADDRESS_DIRECTORY_WARM_LOCALITIES="Москва,Санкт-Петербург,Липецк"
ADDRESS_DIRECTORY_WARM_SCHEDULE=true
```

При включении `WARM_SCHEDULE` команда запускается Laravel scheduler каждый час.
Если upstream недоступен и возвращаются старые данные, команда завершится
с ошибкой, не отмечая их как свежие.

После изменения .env надо обновить конфигурацию приложения штатным способом.
Не надо очищать весь Laravel cache без необходимости — там же остаются
последние успешные списки справочника.

## Ограничение во время аварии самого хостинга

Это защищает от **отключения внешнего адресного API**, когда backend магазина
и его кэш продолжают работать. Если недоступен сам backend магазина или
его БД/Redis, никакой серверный кэш не сможет отдать ответ клиенту.
Поэтому размещение хранилища кэша и реплики адресного сервиса у разных
провайдеров — отдельная задача обеспечения отказоустойчивости.

Запасная форма ручной заявки не заменяется этим механизмом: неизвестный адрес
не подтверждается автоматически, стоимость доставки и наличие проверяются
после восстановления штатного сервиса.
