# Магазин населённого пункта

Магазин — самостоятельная публичная точка с адресом из справочника, контактами и расписанием. Связь со складом необязательна. При связи магазина с собственным складом они используют общую физическую площадку; второй учёт остатков не создаётся.

`GET /api/v1/stores/current?directory_external_id=<ID населённого пункта или здания>`

Ответ: `store` — обычный StoreResource (телефон `phone`, адрес `address`, расписание `opening_hours`, часовой пояс `timezone`, населённый пункт `locality`, необязательный `warehouse_id`) либо `null`.

Детальная карточка `GET /api/v1/products/{slug}` с тем же `directory_external_id` дополнительно возвращает `product.local_store` в таком же формате. Это контакты местного магазина, а не обещание наличия товара или самовывоза.

Выбираются только активные магазины с площадкой в том же населённом пункте по `externalId` и `source`. Совпадение текстового названия не используется. Если магазинов несколько, применяется `priority` (меньше — выше), затем ID. Без адресного контекста или без местного магазина возвращается `null`, соседний город не подставляется. При недоступном адресном справочнике отдельный endpoint возвращает 503.

Ближайший склад товара и доступность доставки по-прежнему определяются отдельным складским механизмом. Магазину не нужны остатки для публикации контактов. Самовывоз доступен только при выполнении проверок склада и остатков.

Фронтенд нужно отдельно подключить к `local_store` или `/stores/current`; этот backend-патч сам по себе не меняет видимые контакты SPA.
