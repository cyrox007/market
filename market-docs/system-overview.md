## Продажа товара: идентичность, остаток и цена

`GET /api/v1/products`, `/products/search`, `/products/count`, `/products/{slug}` работают с самостоятельными товарами и конкретными предложениями SKU. Родитель вариативной группы — контейнер, а не строка продажи. В наличии четыре категории продаж: обычный SKU, предложение группы, продаваемый комплект, предложение вариативного комплекта. Комплекты в корзине представлены **одной логической строкой**, физические компоненты учитываются отдельно.

**Цвета SKU:** после PR #143 цвета больше не являются обычными `variation_attributes`. `ProductColors` отдаёт `colors: [{element, solution}]` с `solution.icon_url` и `solution.base_colors[].hex`. После PR #144 `GET /products` также отдаёт `palette` активных предложений той же группы без ограничения текущей страницей, `/cart` возвращает цвета выбранного SKU, а `/orders/one-click` — цвета SKU и составляющих комплекта. См. [каталог SKU](catalog-individual-sku-api.md).

**Цена**:

1. Базовое `products.price` конкретного SKU.
2. `Services/Pricing/PricingEngine.php` — одна применимая ценовая политика с учётом условий и контекста покупателя.
3. `Services/Pricing/PrivateOfferAccess.php` — цена действующего частного предложения, если применимо.
4. `Services/Product/BundlePricing.php` — фиксированная `bundle_price` комплекта либо стоимость компонентных SKU, согласно композиции.

**Не использовать `product_region_rules` для расчёта цен и разрешения продажи:** прежний механизм выведен из рабочего контура. См. [решение по ценам](retired-product-region-rules.md), [каталог SKU](catalog-individual-sku-api.md), [комплекты из разных складов](bundle-multi-warehouse-stock.md).

**Остатки/доступность:** бэкенд различает физическое наличие, разрешение подзаказа и неизвестный остаток. Не заменять `available_to_order` условием `stock > 0`. Авторитетная складская логика — `StockAvailabilityService`, `CartQuantityPolicy`, `CartFulfillment`.

## Корзина и оформление

| Операция | Маршрут `/api/v1` | Обязательный смысл |
| --- | --- | --- |
| Корзина | `GET /cart` | `items`, `subtotal`, `old_subtotal`, `discount_total`, `item_count` |
| Добавить SKU | `POST /cart` | Увеличение количества, возможная серверная корректировка |
| Задать количество/вариант | `PUT /cart/{itemId}` | Итоговое количество; ID строки может поменяться при замене SKU |
| Удалить строку/всё | `DELETE /cart/{itemId}`, `DELETE /cart` | Изменить серверную корзину |
| Предрасчёт доставки | `POST /shipping/quote` | Проверенный объект здания или сохранённый адрес, серверные тарифы/склады |
| Точки самовывоза | `POST /shipping/pickup-options` | Только доступные источники |
| Прямая покупка | `POST /orders/one-click` | **Подготовка** покупки, заказ не создан |
| Заказ | `POST /orders` | Повторная проверка цены/адреса/резервов, idempotency |

`subtotal` — **текущая сумма товаров, скидки уже учтены**. `old_subtotal` и `discount_total` — сравнительная информация, не дополнительное уменьшение суммы. Если `old_price=null`, не рисовать зачёркивание. Числа и доступность определяет сервер. См. [корзина, сравнение цен](cart-discounts-and-delivery-estimates.md), [пилот жизненного цикла](pilot-checkout-implementation.md).

Для нового заказа `delivery_date` и `delivery_time` запрещены — **нет доступного для бронирования календаря доставки**. `delivery_days_min/max` и `delivery_schedule.status` дают только ориентир, дату и время затем согласует менеджер. Доставка, сборка, подъём, дополнительные услуги и складской источник рассчитываются сервером. Проверку `expected_subtotal`/ответ 409 нельзя обходить. См. [складской контракт](warehouse-only-fulfillment.md).

После создания заказа действует период охлаждения 60 минут; отмена/выполнение/резервы и отправка в 1С проходят серверные проверки. Для платежей и возвратов нельзя приравнивать callback к подтверждённой оплате; необходимо сверять сумму и состояние банка. Изменения банковского цикла Сбера, находящиеся в **незавершённом PR #139**, не считать возможностями `develop` до слияния и проверки. Источники: `services/backend/app/Jobs/ProcessSberbankCallbackJob.php`, `services/backend/app/Services/Order/AutomaticOrderRefunds.php`.

## Адреса и география

1. `directory_external_id` — идентификатор в ГАР/КЛАДР, при доставке требуется **конкретное здание**.
2. `region_id` — отдельный идентификатор бизнес-локации, используемый ценовыми политиками.
3. `warehouse_id`/физическая площадка — место исполнения заказа, не домашний адрес пользователя.
4. `GET /api/v1/address-directory/status` показывает готовность уровней справочника. Частичное покрытие домов не доказывает отсутствие адреса.
5. Адресный сервис — **внешняя зависимость**: `AddressDirectoryClient` вызывает `api.svetofor-mebel.ru`. При его недоступности нельзя обещать тариф/срок без проверки. См. [адресный контракт](address-directory-frontend-launch.md).

**Кэш при аварии:** PR #140 влит в `develop` 06.11.2026. `AddressDirectoryClient` использует короткий свежий кэш и `stale-if-error` для списков/поиска при недоступности upstream; заголовок `X-Address-Directory-Cache: stale` позволяет видеть ухудшение. Подтверждение конкретного здания через `hierarchy()` остаётся строгим и не использует устаревший список; прогрев по расписанию — opt-in. Даже после его включения не разрешать создавать заказ на основании одного устаревшего списка городов/домов.
