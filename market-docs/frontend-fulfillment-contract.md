# Контракт каталога, складов и заявок для фронтенда

Адреса ГАР, готовность уровней, снимки доставки/самовывоза и порядок запуска: [инструкция к запуску](address-directory-frontend-launch.md).

Изменения бэкенда и админки; React не меняется. Наличие кода в `develop` не означает, что сервер уже обновлён.

При развёртывании проверьте существующий `.env`: `ADDRESS_DIRECTORY_PATH=/api/v2/address` (без `/directory`). Явное старое значение окружения переопределяет новый default. После изменения очистите/пересоберите config cache. Источник справочника должен поддерживать эти маршруты; слияние сайта само по себе не обновляет отдельный API-сервис.

## Ответы на пять вопросов

1. `meta.filters.price` — диапазон **текущих цен активных подходящих SKU** в рублях, с региональными правилами и скидкой, не `original_price`. Для вариативного товара учитываются активные варианты; при остальных фильтрах — те же подходящие варианты. Собственный фильтр цены исключён из диапазона. Без местоположения — текущая базовая цена SKU. Исправлены несовпадение базовых/региональных цен и участие неактивных вариантов в отображении. Конкретный старый ответ сервера нужно сравнивать с версией его деплоя, а не считать уже исправленным после локальной проверки.
2. `attributes[slug=proizvoditel].values[].count` — количество уникальных товаров при **остальных** выбранных фильтрах, без собственного выбора производителя (`facet_mode=excluding_self`). Значения одного атрибута соединяются OR, разные атрибуты/габариты — AND на одном SKU. `manufacturer_id`, `manufacturer_slug`, `meta.filters.manufacturers` остаются для совместимости, отмечены deprecated; автоматически в этом релизе не удаляются. Основной контракт — `attr_proizvoditel=a,b`.
3. `width_min/max`, `depth_min/max`, `height_min/max` остаются. `meta.filters.dimensions.{width,depth,height}` содержит `min`, `max`, `unit: "mm"`. Единицы — миллиметры, неизвестный диапазон — null; это характеристики, не коммерческий `size` и не старые физические поля в сантиметрах.
4. Да: `on_sale=1`, `meta.filters.has_sale: boolean`. `has_on_sale` остаётся алиасом для совместимости. Акция означает `original_price > текущая эффективная цена` подходящего SKU.
5. Канонический путь **`POST /api/v1/shipping/quote`**, не `/shipping/quotes`. Передавайте `items`, местоположение справочника и при необходимости бизнес-локацию цен `region_id`. Возвращаются варианты доставки и отдельный `pickup`. `ready` содержит дни и даты; «Сегодня»/«Завтра» только при точном сроке 0/1 день. Пакет `items` — общий расчёт всего набора с одного склада, а НЕ независимый расчёт каждого товара в одном ответе. Для независимых карточек нужны отдельные запросы.

## Карточка без корзины

```json
{
  "directory_external_id": "GUID-объекта-из-нашего-справочника",
  "region_id": 12,
  "items": [{"product_id": 100, "variant_id": 105, "quantity": 2}],
  "requires_assembly": false
}
```

- `product_id` + `variant_id`: вариант должен принадлежать товару и быть активным. Можно передать ID конкретного SKU как product_id без variant_id. Для вариативного родителя вариант обязателен, автоматически самый дешёвый не выбирается.
- `quantity`: целое 1–1000. До 50 позиций; одинаковые SKU суммируются.
- `directory_external_id`: ГАР/КЛАДР из справочника сайта. С `items` можно предварительно считать по региону/населённому пункту (`estimate=true`); при создании доставки требуется здание. Центр города не сохраняется как координата дома.
- `region_id`: отдельный ID бизнес-локации цен, не GUID ГАР. Без него используются базовые цены.
- `address_id` вместо directory_external_id: собственный адрес авторизованного пользователя. Если переданы оба, они должны совпадать.
- Без `items` считается текущая корзина; запрос никогда её не изменяет.

Ответ 200 карточки может содержать `available=false`: это штатное отсутствие доставки, проверьте массив `pickup`. Для корзины отсутствие доставки сохраняет 422. Недоступность адресного сервиса — 503, не «нет покрытия».

## Доставка и сроки

`options[]`, `selected`: warehouse_id, profile_id, stock_mode, transport_cost, handling_cost, delivery_cost, assembly_cost, additional_services_cost, total_fulfillment_cost, processing_days_min/max, transit_days_min/max, delivery_days_min/max, delivery, distance_km.

- Цены в рублях. `delivery_cost = transport_cost + handling_cost`; `total_fulfillment_cost` включает также сборку и прочие услуги, но не товары.
- `delivery_days_min/max = preparation + transit`. `delivery` содержит `days_min/max`, `date_min/max` в YYYY-MM-DD, `day_type=calendar`, `timezone=Europe/Moscow`.
- Сборка имеет отдельный assembly_days и не незаметно добавляется к перевозке.
- Это не дорожный маршрут: `distance_type=straight_line`, километры, неизвестное расстояние — null.
- Старое `product.delivery_days` остаётся правилом прежней системы, `delivery_days_source=legacy_region_rule`; не используйте его вместо warehouse quote.
- При заказе цена/доступность пересчитываются, остаток выбранного склада резервируется в транзакции. Переданная клиентом сумма не является тарифом.

## Остатки и сортировка

Складской остаток для выбранного местоположения учитывает активность склада, режим quantity и новое покрытие (территории/радиус/гибрид). Профиль с необработанными constraints не используется. Старые явные привязки локаций поддерживаются только для склада без новых профилей.

- `stock=null`, `stock_known=false`: достоверного складского учёта нет; глобальный products.stock не выдаётся за местный.
- `stock=0`: подходящего фактического остатка нет. `stock_scope=destination/global` различает контекст.
- `in_stock` — только положительный фактический остаток. `available_to_order` отдельно отражает подзаказ, не прибавляется к stock.
- Родитель может агрегировать остатки активных SKU; при заказе всегда выбирается конкретный SKU.
- `sort_by=distance`: ближайший активный quantity-склад с остатком минимум одной единицы подходящего SKU и покрытием. Расчёт в SQL **до пагинации**; неизвестные расстояния в конце, далее ID как стабильный tie-breaker. Порядок всегда от ближнего к дальнему. Передайте directory_external_id, либо бизнес-локацию с парой latitude/longitude. Нет точки — расстояния null, склад не выдумывается.
- Кеш учитывает географию, фильтры и ревизии складов/профилей/остатков/региональных цен. Изменения 1С тоже инвалидируют ревизию.

## Самовывоз

`pickup[]`: warehouse_id, store_id (null для самого склада), address, hours, opening_hours, items[].available_quantity, pickup_cost=0, ready.

Только действующие физические quantity-склады с достаточным остатком всего набора. Выдача со склада включается отдельно. Магазин должен быть действующим, разрешать выдачу и находиться на той же площадке, что связанный склад. Фабрики/виртуальные источники не являются точками самовывоза.

`ready` — календарная готовность товара после подготовки, НЕ обещание открытой двери: часы работы проверяются отдельно по графику точки. Готовность не является бронированием.

Для нового заказа самовывоза передайте `delivery_type=pickup`, warehouse_id и store_id из выбранной опции. Сервер повторно проверяет точку и резервирует этот склад. Услуги доставки в самовывоз не подставляются.

## Дополнительные услуги

В профиле склада оператор выбирает `services_location_id` — бизнес-локацию с уже настроенными тарифами услуг. Это отдельная настройка от ГАР-покрытия. В quote и заказе:

```json
{"delivery_handling_type_id": 3, "delivery_floor": 4, "requires_assembly": true, "additional_services": [{"id": 8}]}
```

Сервер проверяет доступность, этаж и тариф. `additional_services[].price` запрещён. Поддерживаются фиксированные услуги; услуги «от» и по согласованию нельзя выдавать за окончательную цену — они требуют менеджера. Не настроенный тариф возвращает 422, а не бесплатную услугу.

## Купить в один клик — прямое оформление

`POST /api/v1/orders/one-click` подготавливает выбранный SKU к оформлению:

```json
{"product_id":100,"variant_id":105,"quantity":1,"region_id":12}
```

200 — `{mode:"direct_checkout",items:[{product_id:105,quantity:1}],unit_price,subtotal,submit_endpoint:"/api/v1/orders",message}`. 422 — неправильный SKU/количество; 429 — ограничение частоты.

Фронт открывает обычное оформление с возвращёнными `items`, минуя корзину. Ни заявки, ни заказа, ни резерва на этом шаге нет. При подтверждении отправьте `POST /api/v1/orders`: обычные контактные данные, оплату, доставку, `items` (ровно один товар/вариант), `accept_offer:true`, `accept_personal_data:true`. Сервер повторно проверяет цену, SKU, остатки и доставку и создаёт обычный заказ. Существующая корзина не меняется и не очищается. Старый контракт заявок заменён; React ещё не подключён.

## Магазины и региональный текст

Категория возвращает необязательный `popular_title` (строка до 255 символов или null), редактируемый в админке как «Заголовок блока популярных товаров». Фронт выводит непустое значение как обычный текст; при null, отсутствии или пустой строке — «Популярные товары». Название категории для этого заголовка не склоняется и не дописывается. Поле независимо от `description`, `regional` и `seo`.

`stores.hours` сохраняется. `opening_hours` — null для не заполненного графика или массив `{day:1..7,is_closed,intervals:[{opens:"09:00",closes:"18:00"}]}`; `timezone` — IANA. Неуказанный день неизвестен, а не автоматически выходной. Ночные интервалы через полночь не поддерживаются этим контрактом.

В категории отдельный `regional_text_template`, подстановки `{category_name}`, `{city}`, `{delivery_cities_count}`. Ответ `regional` содержит text/city/delivery_cities_count/count_source; description не изменяется. Город берётся из проверенного справочника/бизнес-локации, без автоматического склонения. Число городов считается по явным населённым пунктам активных источников товаров категории. Для покрытия целым регионом/радиусом точное число неизвестно: null, и шаблон с такой подстановкой не рендерится. Произвольное «ещё 15 городов» не генерируется.
