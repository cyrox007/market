# Временное отключение публичной регистрации и входа

Админка: **Настройки → Вход и регистрация на сайте**. Доступ к переключателям
имеют роли `admin` и `super_admin`, проверка выполняется и при сохранении.
Оба переключателя по умолчанию включены. Вход Filament в админку не меняется.

- Регистрация выключена: `POST /api/v1/auth/register` → 403,
  `code=public_registration_disabled`. При гостевом заказе аккаунт не создаётся,
  но сам заказ разрешён; существующие пользователи не удаляются.
- Вход выключен: `POST /api/v1/auth/login` → 403,
  `code=public_login_disabled`. Автоматический вход после регистрации и создания
  заказа также запрещён. Уже открытые сессии не отзываются, выход работает.
- Регистрация включена, вход выключен: аккаунт создаётся без входа,
  ответ регистрации содержит `authenticated: false`. Ответ заказа может
  содержать `user_registered: true, user_authenticated: false`.

`GET /api/v1/auth/settings` публично отдаёт только:

```json
{"data":{"registration_enabled":true,"login_enabled":true}}
```

Ответ `no-store`. Сервер проверяет БД на каждом входе/регистрации. Фронт
проверяет настройки перед показом формы, при фокусе и каждые 30 секунд.
При недоступности настроек показывает повтор, не разрешая форму по догадке.
Изменение администратором применяется на API сразу; уже открытая форма
получит понятный 403, даже если ещё не успела обновить настройки.

Для развёртывания нужна только миграция
`2026_10_22_130000_create_public_auth_settings_table.php` и обновление кода.
Она создаёт отдельную небольшую таблицу, не изменяя аккаунты или сессии.
Рабочие публичные регистрация и вход не отключаются самим развёртыванием.
