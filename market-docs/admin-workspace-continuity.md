# Непрерывная работа оператора

## Сессия

- Открытая админка продлевает сессию раз в минуту, в том числе без активности и в фоновой вкладке.
- Перед Livewire-действием проверяется действующий вход и получается актуальный CSRF-токен. Действие отправляется один раз, без автоматического повторения и перезагрузки формы.
- При используемом на сервере `SESSION_DRIVER=database` учётные записи с ролями `super_admin`, `admin`, `manager`, `editor`, `viewer` получают запас на сон/приостановку браузера: `OPERATOR_SESSION_LIFETIME=720` минут. Обычные покупатели сохраняют `SESSION_LIFETIME=120`.
- Общая сборка мусора хранит строки сессий не меньше операторского TTL, однако чтение просроченной покупательской сессии по-прежнему запрещено. Выход удаляет сессию; отзыв ролей не даёт продлить её как операторскую.
- Веб-запросы используют существующий StartBlockingSession: изменяющие запросы сериализуются, неизменённая сессия при GET продлевается без перезаписи старого снимка. Это снижает риск гонки фонового запроса с входом/выходом.
- Смена пользователя в другой вкладке не позволяет отправить старую форму от имени нового пользователя. Настоящий выход, отзыв доступа или перерыв дольше TTL требуют входа; форма не сбрасывается.

## Черновики

- Для Livewire-компонентов с основным состоянием формы `data` сохраняются изменения в зашифрованном виде (AES-GCM) в sessionStorage текущей вкладки. Срок черновика — 24 часа.
- Ключ выводится из отдельного контекста и ID пользователя с помощью HMAC; APP_KEY не передаётся браузеру. Сам ключ черновика не сохраняется в sessionStorage. При новом входе того же пользователя сервер выдаёт тот же производный ключ. Это защита локального хранения, не защита от XSS в уже открытой авторизованной странице.
- Восстановление после F5 изменяет только данные формы, не выполняет сохранение, заказ, оплату, импорт или иное действие.
- Если исходные данные на сервере изменились, автоматического восстановления нет: оператор выбирает серверную версию или свой черновик.
- Подтверждённое сохранение Filament (`RecordSaved`) удаляет черновик. Ошибка валидации его сохраняет. Явный выход очищает черновики этого пользователя в текущей вкладке.
- Пароли, токены, ключи и временные ссылки Livewire-загрузок исключаются. Файлы, ещё не загруженные браузером, и содержимое диалогов действий (`mountedActions`) не восстанавливаются. Это не резервная копия файлов, не автосохранение в БД и не универсальный черновик произвольного пользовательского редактора вне `data`.
- При недоступном локальном хранилище или незавершённом шифровании перед уходом появляется стандартное предупреждение браузера о несохранённых изменениях.

`node --test tests/js/admin-session-recovery.test.cjs`

Изменения локальные. Для выпуска нужны PHP-файлы обработчика/провайдеров/маршрутов/конфигурации, Blade-шаблоны и `public/js/admin-workspace.js`. Миграций для этого механизма нет. После доставки очистить/пересобрать конфигурационный и маршрутный кэш штатной процедурой; выполнить проверку на тестовой операторской учётной записи. Уже открытые старые вкладки должны один раз загрузить новую версию после сохранения работы.
