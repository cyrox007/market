# Пробный ГАР: потоковый разбор Липецкой области

> Исторический прототип. Python-утилиты удалены. Рабочий импорт теперь находится в
> API на Node.js; для сайта используйте [актуальный контракт](address-geolocation-contract.md).

Источник: `D:/gar_xml.zip`. `version.txt` сообщает `2026.10.06`, `v.298`;
имена XML содержат дату 20261005. Полная распаковка не нужна.

## Безопасный пробный запуск

```powershell
storage/geodata/tools/Scripts/python.exe -X utf8 scripts/geodata/stage_gar.py D:/gar_xml.zip --region 48 --output storage/geodata/gar-48.sqlite
storage/geodata/tools/Scripts/python.exe -X utf8 scripts/geodata/audit_gar.py storage/geodata/gar-48.sqlite storage/geodata/customer-localities.sqlite
storage/geodata/tools/Scripts/python.exe scripts/geodata/test_stage_gar.py
```

Python использует стандартные zipfile, ElementTree и SQLite; osmium не требуется.
Из ZIP читаются только шесть региональных файлов: объекты, здания, параметры объектов,
параметры зданий, административная и муниципальная иерархии. Также читаются version.txt и типы параметров.
XML разбираются по записям с ограниченным расходом памяти. Рабочая база API, Laravel
и действующий географический снимок не изменяются.

Выходной файл создаётся рядом как `.building.sqlite`; завершённый снимок публикуется
переименованием только после успешного разбора ZIP и SQLite integrity_check. При ошибке
остаётся промежуточный файл для диагностики, не готовый справочник. Существующие
файлы не перезаписываются; повторный запуск требует нового имени.

- Только ISACTUAL=1: порядок исторических версий в XML не влияет на актуальную запись.
- ISACTIVE сохраняется отдельно: снятые с действия актуальные версии не теряются.
- Параметры выбираются на дату версии архива, с незавершённым CHANGEIDEND.
- Код КЛАДР и почтовый индекс определяются через AS_PARAM_TYPES, не угадываются.
- Дополнительные номера/типы зданий и все исходные атрибуты сохраняются в raw.
- Несколько текущих версий объекта или параметра приводят к ошибке, не к случайному
  выбору последней записи.
- Проверяются пропущенные родители, отсутствующая иерархия, повторяющиеся коды КЛАДР
  и циклы. Проблемы в исходных данных отражаются в отчёте, а не скрываются.
- Муниципальная иерархия хранится отдельно и не перезаписывает административного
  родителя. Объекты уровней 3/4 могут законно отсутствовать в административной иерархии.

Для дополнения уже проверенного административного снимка муниципальной иерархией
используется `--staged-input <old.sqlite>` с новым выходным именем. Версия архива,
регион и статус исходного снимка проверяются; исходный файл открывается только для чтения.

## Почему пока не запускать старый импортёр API

Проверенный `GarAddressImportService` в api.local принимает распакованную директорию,
пишет исторические записи в те же строки без выбора актуальной версии и не читает
AS_*_PARAMS. Старый путь сначала распаковывает весь архив. Это не подходящий путь для
57,8 ГБ ZIP/429 ГБ XML. Перед загрузкой в рабочую MySQL нужно исправить этот путь,
проверить уникальность kladr_code, обработку снятых с действия записей и возможность
повторного запуска. Пробный SQLite не означает, что рабочий API уже обслуживает ГАР.

Для совместимости с сайтом аудит соединяет ГАР с текущим КЛАДР по фактическому CODE,
не по названию. Координат в ГАР этот разбор не создаёт: они берутся из OSM-снимка,
если соответствующий код уже сопоставлен.

## Результат реального прогона 08.10.2026

Готовый изолированный снимок: `storage/geodata/gar-48-complete.sqlite`.
Сохранены 12 649 актуальных версий адресных объектов и 331 976 актуальных версий
зданий (в том числе снятые с действия, с отдельным флагом). Административных связей
322 767, муниципальных 322 866. SQLite integrity_check = ok.

Пропущенных родителей, циклов, действующих объектов без обеих иерархий и повторных
кодов КЛАДР среди действующих объектов не обнаружено. 117 муниципальных объектов
закономерно не имеют административной связи, но имеют муниципальную.

В ГАР 1 611 действующих населённых пунктов области; все имеют код КЛАДР.
1 607 кодов уже присутствуют в действующем снимке сайта; 143 связаны с координатами
OSM текущим консервативным алгоритмом. Липецк: ГАР OBJECTID 799573,
GUID eacb5f15-1a2e-432e-904a-ca56bd635f1b, КЛАДР 4800000100000,
координаты 52.6051488 / 39.5963775.

У зданий в этой выгрузке нет параметра CODE (КЛАДР): нельзя придумывать
однозначное соответствие старым сгруппированным записям buildings. Старый
справочник зданий следует оставить для совместимости, новые здания адресовать
по GUID ГАР. Рабочий API и сайт на этот ГАР-снимок пока не переключены.
