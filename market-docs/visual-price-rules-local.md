# Ценовые политики — локальная реализация

Ветка `feature/visual-price-rules`. Сервер, React и импорт адресов не изменяются.

## Как настроить

Админка → Товары → **Ценовые политики** → Создать ценовую политику. Группы покупателей и подборки создаются прямо из редактора. Управление общими группами и прежние настройки доступны через меню «Дополнительно» в списке политик; отдельных пунктов в боковом меню нет.

1. Название и переключатель. Новое правило выключено: сначала заполните и проверьте его.
2. Товары: все / конкретные товары и SKU / несколько категорий с потомками / комнаты / именованные подборки. Выбор родительского товара включает варианты. Исключения имеют преимущество.
3. Покупатели: все / гости / зарегистрированные / конкретные / группы / условия. Группы покупателей независимы от административных ролей.
4. Действие: скидка или наценка в процентах/рублях либо новая фиксированная цена. Рубли — на одну единицу. Итог не бывает отрицательным; денежные суммы округляются до копеек.
5. Начало и окончание по Москве. Пустые даты не ограничивают действие; окончание исключительное. Отключение действует сразу.
6. В «Проверить перед сохранением» выберите конкретный SKU, покупателя (пусто — гость) и при необходимости регион. Расчёт использует несохранённую форму и текущую дату, но не изменяет товар/правило. Выключенное правило не применяется.

Подборки и группы покупателей редактируются в отдельных простых списках. До 500 элементов на группу/выбор. Состав применяется всеми связанными правилами; пустой список не превращается во «всех».

## Пересечения и региональные цены

Сначала определяется прежняя региональная цена, затем применяется **одно** подходящее новое правило: больший приоритет, при равенстве — меньший ID (созданное раньше). Скидки не складываются. Копия правила всегда выключена.

Скрытие товаров и прежние сроки доставки остаются региональными настройками, не смешиваются с акциями. Старые записи не удалены. Прежнее поле «товар не выбран — все товары» не используется новым редактором: для общего правила есть явный выбор «Все товары».

Комнаты используют существующие категории и ограничения, включая наследование. Ценовые ограничения комнаты проверяются по региональной цене **до** новых акций, чтобы правило не определяло само собственную применимость.

Условия покупателя объединяются «И»: минимум/максимум доставленных заказов, сумма товаров в доставленных заказах и возраст аккаунта. Гости не удовлетворяют этим условиям; неоплаченные/отменённые заказы не считаются. Нулевой максимум позволяет выбрать пользователей без доставленных заказов. Это не произвольный язык программирования условий.

## Согласованность и безопасность

Расчёт SQL используется до пагинации: цены, диапазоны, фильтры, count и сортировка по цене согласованы. Карточка, корзина, quote и оформление используют тот же механизм. Персональность определяется по авторизованному пользователю, а не переданному user_id/email. На оформлении контекст фиксируется **до** авторегистрации.

Ценовые API-ответы имеют `Cache-Control: private, no-store` и Vary Cookie/Authorization. Внутренние ключи учитывают пользователя, подходящие правила, географию и ревизию. Смена временного окна меняет ключ без cron. Изменения правил и групп инвалидируют ревизию.

Фронтенд не изменялся: для персональной цены запрос обязан передавать сессию либо Bearer-токен. Гостевой SSR остаётся гостевым; при входе/выходе клиент должен заново запрашивать цены. Нельзя сохранять персональный API-ответ в общем SSR/CDN-кеше, игнорируя заголовки сервера.

Новая скидка отображается через существующие price/old_price/discount_percent и on_sale/has_sale; структуру React менять не требуется. В order_items.pricing_snapshot сохраняются исходная/региональная/итоговая цены, правило и время расчёта. Изменение правила не переписывает созданные заказы.

Изменения правил записываются в pricing_rule_changes: кто, когда, до и после. Удаление мягкое. Просмотр/изменение доступны manager/admin/super_admin; другие роли не получают редактор. Историю пока читают из БД: отдельного журнала в UI нет.

Локальная миграция: `2026_10_15_110000_create_visual_pricing_rules.php`, только БД сайта laravel. Тесты — SQLite; дополнительная проверка SQL — `tests/Manual/PricingMysqlSmoke.php` с откатом временных записей.

Проверено 15.10.2026: полный прогон PHPUnit — 569 тестов, 2296 assertions, без ошибок и падений (32 предупреждения PHPUnit об устаревших API). Проверены создание/редактирование, результат несохранённого предпросмотра, запрет для viewer, сроки, группы, условия, категории/комнаты, акция без original_price, персональные каталог/count/карточка/корзина/заказ и сохранение снимка цены. Реальный локальный MySQL: персональная цена 875 ₽ и гостевая 1000 ₽ для одного SKU; временные записи откатились.
