# Оперативные исправления каталога — локальный контракт

Ветка `feature/catalog-api-quick-fixes`, основана на локальной ветке бэкенда адресов/доставки. Реализация только на бэкенде; React, прод и PR #77 не обновляются этим этапом.

## Сортировки

`GET /api/v1/products?sort_by=price&sort_order=asc`

Допустимые `sort_by`: `created_at`, `price`, `name`, `units_sold`, `rating`. Направление: `asc` или `desc`. По умолчанию `created_at desc`. Для популярности — `units_sold desc`, для рейтинга — `rating desc`.

Эти же сортировки и дополнительный порядок по ID действуют в отдельном `/products/search?q=…`.

Рейтинг — средняя оценка одобренных отзывов родительского товара, округлённая до одного знака; при отсутствии отзывов — 0. Во всех сортировках дополнительный порядок `products.id asc`. Он устраняет случайный порядок при равенстве значений, но не создаёт снимок каталога: изменения цен, оценок или состава товаров между запросами могут сдвигать страницы offset-пагинации.

## Лёгкий подсчёт

`GET /api/v1/products/count?category_slug=divany&attr_proizvoditel=factory-a,factory-b&on_sale=1`

```json
{"total":12}
```

Использует ту же цепочку ограничений, что `/products`: категория/категории, комната, поиск, цены, характеристики, производитель, видимость в переданной локации, акции. Считает родительские карточки, не SKU. Не загружает карточки/медиа/варианты и не строит `meta.filters`. Параметры страницы/размера страницы не влияют на total. Валидация — 422 с `errors`.

## Акции

`on_sale=1` — только товары по акции. `on_sale=0` или отсутствие параметра — без ограничения по акции, **не** «только без акции».

Акция: `original_price > price`. У обычного товара проверяются его цены, у вариативного — наличие хотя бы одного активного акционного варианта. Одной старой цены родителя при отсутствии акционных активных SKU недостаточно. Неодобренные/неактивные SKU не делают карточку акционной.

`meta.filters.has_on_sale` показывает наличие акционных карточек в области фильтров категории/комнаты/набора категорий, до применения `on_sale`. Это булевый признак, не количество.

Ограничение этапа: сравниваются базовые сохранённые цены, не индивидуальные/региональные скидки. Совместное совпадение всех характеристик и акции на одной SKU относится к отдельному этапу нормализации вариативных фильтров; сейчас акция означает наличие активного акционного предложения в карточке.

## Несколько категорий

`category_slugs=divany,krovati` или `category_slugs[]=divany&category_slugs[]=krovati`.

OR между выбранными категориями, каждая включает всех потомков. Карточка в двух категориях не дублируется. Остальные фильтры применяются через AND. Если одновременно переданы старые `category_slug`/`category_id`, они дополнительно сужают область, не заменяются списком. Неизвестный slug в списке — 422, а не незаметное расширение выдачи. Максимум 100 slug, по 255 символов.

## Комнаты и meta.filters

Для `room_slug` теперь возвращается объект `meta.filters` того же формата: `price`, `colors`, `sizes`, `attributes`, `manufacturers`, `has_on_sale`. Область комнаты включает категории её подкомнат и ограничения комнаты. Для комнаты метаданные дополнительно отражают применённые фильтры характеристик; для категории сохранено прежнее поведение — варианты характеристик строятся до фильтрации по ним. Самоисключающиеся фасетные счётчики — отдельный этап, не реализованы.

Кеши разделены по комнате, набору категорий, ограничениям и переданной локации. Изменения товаров/отзывов обновляют ревизию нового каталожного кеша. Для общего каталога без категории/комнаты `meta.filters` по-прежнему может быть null.

## Производители

Основной контракт для текущего наполнения: `attr_proizvoditel=factory-a,factory-b` — OR по значениям, AND с остальными фильтрами. Неизвестное значение не возвращает весь каталог.

В `meta.filters.attributes` найти запись `slug=proizvoditel`, затем `values`: `id`, `name`, `slug`, `count`. Count — число различных родительских карточек в области фасета, а не сумма вариантов/остатков. Неактивные варианты исключены из подсчёта.

В админке характеристика «Производитель» должна иметь slug `proizvoditel`, включённое использование в фильтрах и значения, привязанные к товарам/активным вариантам. Изменений справочника на проде, автоматической миграции производителей и объединения двух источников данных не выполнялось. Старые `manufacturer_id`, `manufacturer_slug` и `meta.filters.manufacturers` сохраняются как отдельный совместимый механизм, не подменяют характеристику.

## Проверки

`CatalogQuickFixesTest`: устойчивый порядок равных значений, рейтинг, акции обычных и вариативных карточек, отсутствие полной загрузки в count, категории с потомками/без дублей, комнаты и изоляция кешей, производители и счётчики, ошибки параметров.

Размеры диапазонами, сортировка по удалённости складов, новый расчёт на карточке, самовывоз и «Купить в один клик» в этот этап не входят.
