# География и адреса: контракт для фронтенда

Обновлено 09.10.2026. Описывает подготовленный контракт бэкенда. Локальное окно React
подключено к поиску и определению населённого пункта; редизайн не выполнен.
До выкладки кода и завершения импорта не считать боевой API полностью
переключённым на ГАР. Покрытие проверяется отдельным запросом статуса.

## Три разных сущности

- **Населённый пункт пользователя** — объект адресного справочника ГАР. Это выбор
  города/посёлка на сайте, а не запись административного раздела «Локации».
- **Адрес доставки / физический адрес склада** — конкретное здание ГАР. Корпус и
  строение входят в запись здания. Квартира, комната, этаж, подъезд и комментарий —
  пользовательские дополнения; они не меняют GUID здания.
- **Зоны и правила доставки** — бизнес-настройки: откуда, куда, цена, срок, услуги.
  Они не заменяют географический справочник. Пересадка адреса склада на ГАР не
  означает, что зоны и тарифы должны стать адресными объектами.

ID адресного объекта — строка GUID. Не преобразовывать в число. Поле `objectId`
ГАР тоже строка (большое целое). `kladrCode` — строка совместимости, сохраняющая
ведущие нули; может быть null. Не вычислять GUID/КЛАДР-коды самостоятельно.

КЛАДР-код не гарантирует уникальность: одному коду могут соответствовать несколько
объектов ГАР. Для выбранного населённого пункта и здания всегда передавать GUID.
Неоднозначный КЛАДР-код API отклоняет, а не выбирает первую совпавшую запись.

## Куда обращаться

Локальный прототип хранит подтверждённый выбор в `localStorage.customer_locality`
отдельно от числового ID складской локации. Шапка показывает населённый пункт.
GPS передаётся только для поиска, координаты пользователя не сохраняются.
Населённый пункт без сопоставленной зоны тоже можно выбрать; это не обещает
доступность доставки. Пока внешний API возвращает `source=kladr`, прототип
принимает совместимые 13-значные ID; после переключения ГАР получает GUID.
Это временная совместимость, не подтверждение завершения импорта ГАР.

Клиент сайта обращается к **бэкенду самого сайта**, относительные URL ниже.
Бэкенд подключается к `ADDRESS_DIRECTORY_BASE_URL=https://api.svetofor-mebel.ru`.
Не зашивать внешний хост в React. Импортные/admin-токены клиенту не нужны.

Публичные запросы используют независимые именованные ограничители: чтение —
120/мин, определение координат — 30/мин по умолчанию. Настройки бэкенда:
`ADDRESS_DIRECTORY_READ_RATE` и `ADDRESS_DIRECTORY_GEO_RATE`. Это защитные
стартовые значения, не измеренная пропускная способность; корректировать по нагрузке.
Для авторизованных ключ — ID пользователя, для гостей — IP (общая сеть делит квоту).
Поиск не расходует квоту определения и наоборот. Поиск выполняется с debounce
400 мс и отменой устаревших запросов; ответы справочника кешируются сервером.
При 429 учитывать `Retry-After`/`retry_after`, показывать ожидание, не запускать
повторные запросы до его окончания. GPS автоматически не повторять.

## 1. Определение населённого пункта по координатам

Координаты получает браузер через `navigator.geolocation` только после разрешения.
Сам по себе бэкенд не получает GPS и не определяет точный город по IP.

```http
POST /api/v1/localities/detect
Content-Type: application/json

{"latitude":52.605,"longitude":39.596}
```

```json
{
  "data": [{
    "kind": "locality",
    "externalId": "eacb5f15-1a2e-432e-904a-ca56bd635f1b",
    "kladrCode": "4800000100000",
    "name": "Липецк",
    "label": "Липецкая, Липецк",
    "source": "gar",
    "latitude": 52.6051488,
    "longitude": 39.5963775,
    "coordinatePrecision": "settlement_centre",
    "distanceKm": 0.03
  }],
  "meta": {
    "requiresConfirmation": true,
    "method": "nearest_settlement_centres",
    "radiusKm": 25,
    "attribution": "© OpenStreetMap contributors, ODbL"
  }
}
```

Это ближайшие **центры населённых пунктов**, не точное попадание в административную
границу и не адрес пользователя. Показывать «Ваш город — Липецк?» с подтверждением
и кнопкой ручного выбора. При отказе в GPS, таймауте или `data: []` сразу предложить
ручной поиск. Не подставлять первый склад/регион по умолчанию.

GPS пользователя не сохраняется этим запросом. Не записывать координаты в логи,
localStorage или аналитические события. Хранить подтверждённый ID населённого пункта,
а не результат каждого геозапроса. Отдельного API сохранения предпочтения города
в аккаунте пока нет: клиент передаёт выбранный ID при резолве назначения.

## 2. Ручной выбор населённого пункта

```http
GET /api/v1/localities/regions
GET /api/v1/localities?region=REGION_GUID&q=Лип
GET /api/v1/localities?q=Лип
```

Ответы имеют вид `{"data": [...]}`. Регионы: `externalId`, `name` и другие поля
классификатора. Населённые пункты: `externalId`, `kind`, `name`, `type`, полный `label`,
`source`, `kladrCode` и nullable-координаты. Показывать `label`, чтобы различать
одноимённые населённые пункты разных регионов.

`region` — GUID региона ГАР, не ID из «Локаций». Без региона поисковая строка должна
содержать минимум 2 символа; иначе список пуст. Результат ограничен 50 записями:
это не полный список всех городов региона, нужно уточнять поиск. В отсутствие
координат населённый пункт всё равно доступен для ручного выбора.

После подтверждения получить проверенный объект:

```http
GET /api/v1/localities/LOCALITY_GUID
```

Ответ: `{"data": {...}, "shippingLocation": {...} | null}`. `data.regionExternalId`
— GUID региона; `data.regionKladrCode` — его код совместимости. `shippingLocation`
— временный адаптер к существующим бизнес-локациям доставки, **не ID выбранного
населённого пункта**. Null означает, что доставка для города ещё не настроена,
а не что город не существует. Не заменять его произвольной складской локацией.

Существующий мост назначения:

```http
GET /api/v1/regions/detect?locality_external_id=LOCALITY_GUID
```

Ответ содержит `locality`, `region` (бизнес-локация либо null), `source=address_directory`.
У этого маршрута удалены сторонний IP-поиск и случайный регион по умолчанию.
Он не является новым алгоритмом ранжирования товаров по расстоянию: подключение
выбранного населённого пункта к выдаче товаров и тарифному калькулятору — отдельный
потребитель географического контракта.

## 3. Выбор адреса по иерархии

```http
GET /api/v1/address-directory/regions
GET /api/v1/address-directory/localities?parentExternalId=REGION_GUID&q=Лип&limit=50
GET /api/v1/address-directory/streets?parentExternalId=LOCALITY_GUID&q=Москов&limit=50
GET /api/v1/address-directory/buildings?parentExternalId=STREET_GUID&q=10&limit=50
GET /api/v1/address-directory/hierarchy/BUILDING_GUID
```

Списки возвращают `{"data": [...]}`. Иерархия —
`{"data":{"target":{...},"path":[...],"label":"полный адрес"}}`.
`target.kind` обязан быть `building`. `path` содержит реальные промежуточные
уровни ГАР: не предполагать, что цепочка всегда имеет ровно четыре элемента.

Если здание находится непосредственно в населённом пункте без улицы, запросить
`buildings` с `parentExternalId=LOCALITY_GUID`. Не придумывать название улицы.
При смене региона сбрасывать город, улицу и здание; при смене города — улицу
и здание; при смене улицы — здание. Отмена старого запроса обязательна, чтобы
его ответ не восстановил дочерний выбор от прежнего родителя.

`q` фильтрует по префиксу, поэтому поиск `10` может вернуть `10`, `100` и корпуса:
пользователь выбирает конкретную запись. Для списков `limit` 1–200, по умолчанию 50;
пагинации сейчас нет. Не показывать ограниченный ответ как полный справочник.

## 4. Адреса в профиле

Требуется авторизация (существующая Sanctum-сессия сайта).

```http
POST /api/v1/addresses
Content-Type: application/json

{
  "directory_external_id":"afa660a0-0ca7-4577-afe4-234e5bb5d97a",
  "title":"Дом",
  "apartment":"25",
  "entrance":"2",
  "room":null,
  "floor":"5",
  "intercom":"25",
  "comment":"Позвонить перед доставкой"
}
```

Не отправлять `city`, `street`, `house`, `shipping_location_id`, GUID/КЛАДР-код
отдельными доверенными полями: бэкенд сам получает и проверяет иерархию здания.
Квартира и комната необязательны. Корпус/строение выбираются как часть здания,
а не вписываются вместо квартиры.

Создание возвращает 201 и `{"address": {...}}`. Адрес включает `gar_guid`, nullable
`kladr_code`, `address_snapshot`, `full_address` и введённые дополнения.
Изменение — `PUT /api/v1/addresses/{id}`. Неизменённый `directory_external_id`
не требует повторного обращения к справочнику, поэтому детали старого адреса
можно редактировать во время сбоя API. Передача null для дополнения очищает его.

## 5. Склад в админке

Адрес физического склада выбирается из того же ГАР. При сохранении проверяется
здание и сохраняются `address_external_id`, `gar_guid`, `kladr_code`, полный адрес
и `address_snapshot`. Для собственного склада форма требует выбор здания.
GUID склада в 1С (`external_id`) и GUID здания (`gar_guid`) — разные значения.

Точную точку склада оператор задаёт парой широта/долгота. Она помечается
`coordinate_source=operator`, `coordinate_precision=warehouse_point`.
Координаты центра населённого пункта не копируются в точку склада.
При смене здания старые координаты сбрасываются. Зоны доставки, цены и сроки
настраиваются отдельно и не меняют адресную идентичность склада.

## Ошибки и доступность

- 401/403 — авторизация/владелец адреса.
- 422 — некорректные координаты, родитель/выбор здания или поля формы.
- 429 — лимит запросов; не делать мгновенный бесконечный retry.
- 503 — внешний справочник недоступен или импорт ещё не готов; не показывать
  успешное пустое состояние и не затирать сохранённый выбор.
- Неизвестный населённый пункт: 404, если справочник вернул объект другого вида;
  ошибка внешнего запроса может быть преобразована в 503. Не полагаться только
  на 404 для определения отсутствия записи.

Покрытие внешнего API: `GET https://api.svetofor-mebel.ru/api/v2/address/directory/status`.
`garReady` не означает всю Россию: нужно проверять список завершённых областей
импорта. `nationwideReady` нового контракта подтверждает завершённый общероссийский
scope; региональные пакеты отдельно перечисляются в `gar.imports`.

Точные координаты зданий пока не покрыты сплошным справочником. Null допустим.
Нельзя выдавать центр города за координаты здания или обещать точную дорожную
дистанцию по расстоянию между географическими точками.
