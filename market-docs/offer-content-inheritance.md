# Описание и характеристики торговых предложений

## Проверка production 26.10.2026

У группы «Антресоль Бруно (Тайм)», ID 25812:

- Белый/Белый, SKU 382514, ID 24612: собственное описание `<p></p>`.
- Дуб Вотан/Белый, SKU 382516, ID 25809: также `<p></p>`.
- Венге/Сосна Лоредо, SKU 382517, ID 25810: также `<p></p>`.
- Графит/Графит, SKU 382518, ID 25811: описание null.
- У родителя полноценное описание заполнено.

Прежний API считал `<p></p>` заполненной строкой и блокировал наследование.
Проверка публичного API подтвердила это как в прямой карточке предложения,
так и в `product.variants[]`. Проблема не ограничена старым фронтендом.

На момент проверки общие значения характеристик этих предложений совпадали;
различались значение «Вариант» и порядок строк. Собственная запись атрибута
переносила его в конец, даже если значение совпадало с родителем.
Не утверждаем, что это полностью объясняет прежний скриншот характеристик:
старый фронтенд может дополнительно менять отображение.

## Исправленный контракт

- Пустые абзацы, переносы без текста, HTML-комментарии, неразрывные и
  невидимые пробелы не считаются собственным описанием.
- Прямое предложение и его запись в списке вариантов используют один
  `Product::getEffectiveDescription()`: содержательное своё описание,
  иначе содержательное родительское, иначе null.
- Описание, состоящее из допустимого изображения, остаётся собственным;
  действующий текст и HTML не заменяются родителем.
- Новые пустые значения редактора сохраняются как null. Старые строки
  обрабатываются при чтении, без массового изменения базы.
- Отвязка материализует унаследованное описание; объединение не выбирает
  длинную пустую разметку как наиболее полное описание.
- Собственные непустые характеристики заменяют родительские на прежнем
  месте в списке. Пустая собственная строка не скрывает заполненное общее
  значение. Ноль — полноценное значение, а не пустота.
- Цвет/размер и остальные параметры вариации не наследуются как общие
  характеристики. Список вариантов и прямая карточка используют один метод
  формирования эффективных характеристик.
- Предложение доступно по slug и числовому ID с проверкой активности
  предложения и родителя; кэш числового ID связан с тегом родителя.

В этой доработке фронтенд, тарифы/склады и production-данные не изменяются.
Складской переход ведётся отдельно и не должен попасть в этот PR.
