  В публичной выдаче только активные записи; количество может отличаться. Города административного уровня добавляются как родители/объекты, не переименовываются в БД.
- Публичный `/api/v2/address` подключён к новой таблице: regions/localities/hierarchy проверены HTTP 200.
- Улицы (1318579) и административные объекты (257567) также сверены по количеству. `settlementsReady=true`, улицы готовы; `nationwideReady=false` — дома ещё переносятся.

## Сайт обновлён; требуется финальный сквозной прогон

- Сайт: федеральные/административные города принимаются при выборе адреса склада и доставки.
- Заказ фиксирует `fulfillment_snapshot.address_directory` с GUID, OBJECTID, КЛАДР, кодами родителей, координатами/точностью и деталями квартиры.
- Самовывоз фиксирует адрес площадки/склада, не домашний адрес покупателя.
- Обмен API/1С: `addressExternalId`, `addressDetails`, `warehouseExternalId`; принимающий API сам проверяет GUID и восстанавливает коды.
- Инструкция фронту: `address-directory-frontend-launch.md`.

## Блокирующие проверки до запуска

Аудит боевого сайта: активны физические склады `LP00001` (id=1) и `Во00001` (id=2).
У обоих нет GUID здания и координат; физических площадок и включённых точек самовывоза нет.
Реальные адреса/точки должны подтвердить операторы; автоматически по кодам складов они не выводятся.

1. Проверить принимающий API заказов реальным сквозным тестом: JSON-снимок добавлен и legacy-связи сохранены; боевой тестовый заказ автоматически не создавался.
2. Сайт выложен: `/address-directory/status` и поиск Москвы проверены HTTP 200. Выбор склада, расчёт и создание боевого тестового заказа ещё требуют отдельной приёмки.
3. Каждой рабочей площадке/точке самовывоза назначить конкретное здание ГАР и фактические координаты оператора.
   Не назначать автоматически по похожему названию и не использовать центр города вместо склада.
4. Отдельно загрузить проверенные центры населённых пунктов; зафиксировать покрытие по регионам и список отсутствующих/спорных.
5. После переноса домов — сверка количества, целостности родителей и источников, затем полный ready-флаг; не отмечать готовность вручную.
6. Сквозной прогон доставка/самовывоз → складской остаток → заказ → API → выдача для 1С со всеми кодами и деталями.
7. Отмена заказа должна вернуть остаток тому же складу ровно один раз. Повторная отправка заказа не создаёт дубль.

Реальная координатная готовность, не только число импортированных городов, обязательна для геолокации и фильтра по удалённости.
