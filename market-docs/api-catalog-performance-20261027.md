# API каталога: объём и задержки — 27.10.2026

## Контракт для фронтенда

- Меню категорий: `GET /api/v1/categories/tree?view=menu`.
- Меню комнат: `GET /api/v1/rooms/tree?view=menu`.
- Обычные URL без `view` и `view=full` сохраняют прежние поля: SEO, описание и родителя. Детальную карточку категории следует брать отдельным GET /categories/{slug}, комнаты — /rooms/{slug}.
- Меню содержит id, name, slug, parent_id, icon, full_path, image, image_thumb, children. В нём намеренно нет описаний, SEO, рекурсивного parent, региональных текстов и счётчиков товаров. Не использовать его для вычисления наличия товаров.
- JSON API кодируется с JSON_UNESCAPED_UNICODE. Структура и смысл данных не меняются.

## Кеш и сжатие

Успешные GET categories/tree, rooms/tree, address-directory/regions: `Cache-Control: public, max-age=300`, слабый ETag; `If-None-Match` даёт 304 при неизменном содержимом. Варианты меню/полного дерева и query-параметров имеют разные URL. Ответы с cookies и ошибки не получают публичный кеш. Товары, персональные цены, корзина и заказы остаются private/no-store. ETag и тайминги доступны через CORS exposed_headers.

Меню кешируется в сериализованном виде на сервере на 5 минут, с очисткой при изменении таксономии. Построение использует два массовых запроса: узлы и медиа, без рекурсивных запросов родителей/SEO/региональных расчётов.

В public/.htaccess добавлено DEFLATE для application/json и application/problem+json при доступном Apache mod_deflate. На nginx-only установке нужна настройка gzip на nginx. После деплоя обязательно проверить Content-Encoding и Vary: Accept-Encoding, в том числе ETag/304 с браузерным Accept-Encoding. До этой проверки нельзя утверждать, что боевой транспорт уже сжимает JSON.

На реально полученном публичном дереве до внедрения: 462158 байт. Перекодировка в UTF-8 без экранирования: 262750 байт. Проекция меню: 25335 байт; локальный gzip этой проекции: 3589 байт. Это расчёт на полученных данных, не замер уже изменённого production.

## Скорость товаров

Наблюдения production только чтением: обычный список — 1,18 с целиком при прежнем X-Response-Time=291 мс. Категория matrasy, сортировка units_sold, 12 строк: холодный запрос 44,57 с, повторный 1,17 с. Журнал подтвердил 43741 мс внутри Laravel для холодного запроса, 311 мс для повторного. Следовательно, проблема не сводится к фронту или передаче ответа; есть дорогая холодная ветка. Снимок Redis ping — 5 мс, поэтому его нельзя объявлять доказанной причиной этой задержки.

Изменения холодного расчёта фасетов: min/max цены и каждого размера вычисляются одним агрегатом вместо двух. Совпадающие наборы SKU переиспользуются в пределах запроса; при отсутствии ценовых/атрибутных предикатов не строятся повторные ценовые подзапросы для каждого фасета. До 5000 ID материализуются; более широкие области сохраняют исходный SQL-подзапрос, без обрезки результатов. Семантика excluding_self и наследование значений сохранены.

Запись Redis-метрик перенесена на завершение ответа; постоянная INFO-запись каждого запроса убрана. X-Response-Time теперь включает время PHP от REQUEST_TIME_FLOAT, Server-Timing отдельно показывает php и route. Ожидание свободного обработчика до начала PHP и сеть в эти значения не входят. После выкладки следует отдельно сравнить холодные и повторные запросы; локальные тесты не доказывают время на боевом сервере.

## Популярные товары

На production в момент чтения: 0 товаров с units_sold > 0, 0 доставленных заказов. Важнее другое: подборка featured («Хит продаж») уже ручная, но в ней 0 выбранных товаров. Поэтому заполнение units_sold само по себе не изменит этот блок.

По решению владельца ручной выбор сохранён: в подборке featured выключить автоматический отбор, добавить конкретные товары и задать порядок. В API они выдаются даже при units_sold=0. Автоматический отбор по продажам остаётся отдельным режимом. Статистику продаж искусственно не заполняли; выбор товаров и боевые настройки не изменялись.

## Внедрение

Фронт в рамках изменения не редактировался: его разработчик может переключить только запросы меню на view=menu. Миграции не требуются. Изменения production не выкладывались. Для приёмки нужны повторные реальные замеры gzip/кеша/холодной выдачи после совместного внедрения.

Полный прогон бэкенда: 801 тест / 3448 проверок, без ошибок. Целевые проверки покрывают меню/полный контракт, Unicode, ETag/304, изменение таксономии, изоляцию комнат, приватные цены, сбои справочника, ручную подборку и прежнюю семантику фасетов.

После дополнительной защиты явного no-store/cookies и разделения кеша фасетов по режиму ценообразования: 24 целевых теста / 113 проверок, без ошибок.
