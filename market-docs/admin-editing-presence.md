# Индикация одновременного редактирования

После миграции `2026_11_20_120000_create_admin_editing_presence` и очистки view/config/route
кэшей панель отправляет heartbeat открытой edit-карточки каждые25 секунд. Вложенная
модалка EditAction торгового предложения учитывается как отдельная карточка Product.
В списке показываются имена операторов; другой редактор видит предупреждение.
Сохранение и переходы статусов не блокируются, код заказа не изменён.

Индикация ориентировочная: закрытие страницы освобождает только UUID этого окна,
а при пропаже клиента отметка истекает через90 секунд. Каждый новый page load получает
новый UUID. Данные других вкладок не удаляются. Не считать отметку блокировкой данных.

POST `/admin_sv/editing-presence`: actor_id(пользователь, отрисовавший страницу), window_id(UUID), targets(до30 объектов resource/record),
editing(до5). DELETE по тому же адресу принимает actor_id и window_id. При смене аккаунта в соседней вкладке старый actor_id отклоняется с409, без изменения отметок. Нужны web-сессия, CSRF и
доступ к панели. Просмотр требует policy canView, установка отметки — canEdit.
Принимаются только slug зарегистрированных Filament ресурсов, не произвольные классы.
Ответы no-store; содержат имена, не почту/телефон или поля карточек. Просмотр без прав
редактирования не устанавливает отметку. Очистка истёкших строк выполняется при heartbeat.

Локальная установка на RDP (PHP OpenServer): artisan migrate --no-interaction,
artisan view:clear, при включённых кэшах artisan route:clear и config:clear.
На Beget не выкладывалось. Функциональные тесты endpoint:6/22 assertions; отдельно 3 JS-теста на Livewire proxy, nested edit, восстановление после исключения и UUID fallback на HTTP, включая
TTL, чужое окно, viewer, авторизацию, запрет классов и размер пакета. Визуальную
проверку двух браузерных сессий выполнить отдельно перед публикацией.

## Сводка активности сотрудников на главной (добавлено 23.11.2026, PR #166)

Миграция `2026_11_23_120000_create_admin_panel_presence_table.php` добавляет
`admin_panel_presence`: одна текущая запись на пользователя/вкладку, раздел,
тип страницы (список, создание, просмотр, редактирование), ключ записи, время
последнего подтверждения, срок действия. **История переходов не хранится**.

Существующий `POST /admin_sv/editing-presence` принимает необязательное поле `page`.
Оно совместимо со старой версией клиента; без `page` запись о разделе не
создаётся. Разрешены только зарегистрированные Filament ресурсы и страницы,
для которых есть право `canViewAny` / `canView` / `canCreate` / `canEdit`
соответственно. Произвольные URL, пути, заголовки и поля форм не записываются.
Разметка JS добавляет `page` к тому же heartbeat, что и индикация
редактирования; отдельного HTTP-запроса на каждое действие нет.

Присутствие отправляется только при видимой вкладке и активности пользователя
в последние две минуты. При скрытии вкладки и длительном бездействии отметка
отзывается; если клиент перестал отвечать, запись автоматически теряет
актуальность через 90 секунд. Записи с истёкшим временем удаляются на
следующем heartbeat. Нельзя использовать присутствие для оценки эффективности
труда — это приблизительный индикатор открытого раздела, не запись фактической
работы.

Виджет `AdminUserPresenceWidget` доступен только ролям `admin` и
`super_admin`; обновляется каждые 30 секунд, объединяет вкладки
одного человека, показывает пять сотрудников с раскрытием до пятидесяти.
Прямые ссылки на карточки строятся на сервере лишь при наличии у
просматривающего соответствующих прав. Контент запретного раздела не
раскрывается; отображается «Раздел с ограниченным доступом».

Приёмка: применить миграцию `php artisan migrate --force`, очистить view
cache, проверить две разные сессии, переходы между списком и редактированием,
скрытие вкладки, бездействие свыше двух минут, истечение 90 секунд и доступ
из-под admin/super_admin vs manager/editor/viewer.


Клиентские проверки автоматически выполняет GitHub Actions `Admin editing presence JS tests`.
